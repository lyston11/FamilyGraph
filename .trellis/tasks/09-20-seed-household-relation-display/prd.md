# 演示种子去掉朱元璋在李家 + 家庭卡显示成员关系

## Goal

去掉演示数据里「朱元璋 与 李贞 同处一个家庭空间却看不出任何联系」这一观感问题。用户确认**两件事都做**：

1. 从种子中移除 朱元璋 在「李家」household 的成员资格。
2. 让家庭卡把**服务端已授权的关系称谓**显示在成员上（现在只显示「管理员/成员」标签）。

## 背景事实（已在运行实例与隔离库核实，纠正原始描述）

- 种子里**不存在**「朱元璋–李贞」直接关系边。真实存在的是 `朱元璋 ⇄ 朱佛女 direct_sibling`（姐弟）与 `李贞 ⇄ 朱佛女 spouse`（夫妻）——即 李贞 是 朱元璋 的**姐夫**。
- 「看不出关系」的直接原因是**家庭卡成员投影只带 `household_label`（管理员/成员），不投影关系称谓**；而个人页走 PFV `edges`，所以同一条关系在个人页可见、在家庭卡不可见。
- 进一步实测出**非对称**：`李贞→朱元璋` 能算出称谓（`妻子的兄弟`），`朱元璋→李贞` 算不出（`found=False`）。原因是 `朱元璋` 在「李家」household 内**没有任何结构事实**（他与 朱佛女 是 sibling，而 sibling 不产生 `Relation`），所以从「李家」这个空间出发，viewer=朱元璋 的图里 李贞 是一个孤立节点。

## Requirements

### R1 移除种子里的 朱元璋@李家

- `_SPACE_ROSTERS` 的 `"李家"` 名册不再包含 `朱元璋`。
- 带一条**数据迁移**删除已存在的该成员行（种子收敛是 insert-only，永远不会删行）。判定条件沿用 0052 的既有模式：按（空间名, 用户）精确定位、`status='active'`、且该行由空间 owner 添加（`added_by = family_spaces.owner_id`），确保不会误删真实用户自己的加入申请或管理员批准的邀请。
- 同步更新 `dev_seed.py` 的模块 docstring 与名册注释（第 18、233-235 行）中关于「朱元璋进李家」的描述，不得留下自相矛盾的说明。
- 同步更新 `backend/tests/test_dev_seed.py` 里依赖该成员资格的断言（名册数、成员集合）。

### R2 家族空间只读权限不受影响（回归红线）

- 朱元璋 原本**不在**「李氏家族」lineage（09-19 已修），本次改动不得让任何读取权限扩大或缩小：移除 household 成员资格后，朱元璋 对「李氏家族」仍必须是不可读（404）。
- 该改动不得影响其他 9 对外戚本家的成员资格（朱标@常府/吕府、朱高炽@张家、朱瞻基@孙家、朱祁镇@钱家、宁国公主@梅府）。

### R3 家庭卡成员显示关系称谓

- 家庭卡的每个成员除既有 `household_label`（管理员/成员）外，新增**服务端已授权的关系称谓**（viewer 视角，如「丈夫」「妻子」「姐夫」）。
- 称谓必须来自**后端授权后的确定性解析**（`PERSONAL_FAMILY_VIEW` 同源的图谱口径 + 可见性重验），前端**不得自推**。
- 解析不到路径的成员：`relation_term` 为 `null`，前端不显示占位文案（不泄露「是否存在关系」）。
- 该字段**只加在家庭卡响应上**，不改动 PFV/家族树画布的既有投影形状与渲染。
- 不引入新的可见性级别或权限；不得因为显示称谓而放宽任何读取。

### R4 边界与兼容

- 成员字段保持既有白名单口径：`none` 成员完全不进入投影（不生成占位），成员列表不含 viewer 本人。
- 前端类型与成员卡渲染按新增字段做**可选**处理（旧响应无该字段时不报错）。
- 不改已通过的 ETag/304 与「授权先于 304」语义。

### R5 回归范围

- 新增/更新后端家庭卡测试：成员带 `relation_term`（有路径）与 `null`（无路径）两种；成员字段白名单随之更新。
- 新增/更新迁移测试：迁移只删指定的那一行，且 downgrade 不恢复旧种子值（沿用 0052 的「数据修正不逆向」约定）。
- 更新前端家庭卡测试：显示称谓、无称谓时不显示占位。
- 只运行受影响的后端/前端定向检查 + smoke。

## Acceptance Criteria

- [ ] AC1：种子名册中「李家」不再包含 朱元璋；`test_dev_seed.py` 断言同步且全绿。
- [ ] AC2：迁移在隔离库上执行后，生产等价的旧库中该成员行被删除；只删指定的（空间名, 用户, active, added_by=owner）一行，其他空间与其他行不受影响；downgrade 不恢复该行。
- [ ] AC3：迁移后 `alembic upgrade head` 可正常执行，且 `alembic downgrade` 在任何 DDL 前先执行父级拒绝合同（与 0049/0050/0051/0052 同一约定）。
- [ ] AC4：移除后 朱元璋 读「李氏家族」仍为 404；其他 9 对外戚本家的 household-only 成员保持不变（逐对断言）。
- [ ] AC5：家庭卡成员带 `relation_term`：有授权路径时为该称谓（如 马皇后 视角看 朱元璋 → 「丈夫」），无路径时为 `null`；前端不显示占位。
- [ ] AC6：`relation_term` 仅出现在家庭卡响应；PFV 视图 payload 与家族树画布渲染形状不变（既有画布测试全绿）。
- [ ] AC7：受影响的后端与前端定向检查通过；未运行的高成本检查如实记录。

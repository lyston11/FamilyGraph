# PRD: 家庭账号开通与注册流程

> 状态：规划完成（grilling 三轮收敛，2026-09-05）。待评审后 `task.py start`。

## Goal

家庭前端（FamilyGraph）开放**受控的自助注册**与**邀请码体系**，解决两个问题：
1. **冷启动死锁**：全新部署零账号，OnboardingView 承诺的「开通渠道」不存在。
2. **进入通道**：新家庭无法进入产品、既有家庭无法让家人自助加入——只能靠建档人代办。

系统后台（FamilyGraph 系统管理后台）**保持完全封闭**：不出现任何注册入口、端点或表单。

## 背景

- 09-04-isolated-system-admin-platform 显式推迟：「家庭用户注册和首个家庭账号创建」另立任务。
- commit 57f80eb：OnboardingView 改为静态说明页，家庭端零后台痕迹。
- 后端现状无任何注册端点；账号仅经建档（managed+一次性 PIN）、owner onboarding link 兑换、admin bootstrap 三条路径产生。

## 决策记录（grilling 收敛，2026-09-05）

### 注册
1. **家庭前端开放自助注册；系统后台不开放**。后台 VPN 隔离、零注册面不变。
2. **部署开关**：`REGISTRATION_ENABLED` 配置项，默认开；关闭时前端隐藏注册入口、后端注册端点拒绝。
3. **注册表单**：用户名 + 自选 PIN + 显示名 + **可选邀请码**。
4. **初始状态**：Account 直接 `claimed`（自设 PIN，无强制改密）；Profile `provisional`。
5. **身份确认不自证**：`identity_confirmed` 仅通过家人确认（建档绑定/邀请中的「这是我」确认）获得，复用 identity_fsm 唯一转换点。
6. **反滥用基线**：注册端点按 IP 限流 + 用户名占用防枚举统一文案；登录侧复用既有 AD-2。provisional 用户可建自己的空间，但**不可建码、不可邀请**。

### 邀请码
7. **三种类型**：`household`（家庭空间）/ `lineage`（家族空间）/ `stranger`（陌生人）。
8. **持家庭/家族码** → 加入对应空间：复用既有 SpaceMember `pending→active` 邀请状态机，持码人当场确认接受即 active（注册时填码与设置页填码**同一语义、两个入口**）。
9. **持陌生人码** → 纯拉新归因：记录邀请人/码/时间；注册者得到**自己的独立新家庭空间**，双方之间**没有任何**数据连接或可见性。
10. **自建空间创建者即为 space_admin**（维持现状实现，无「第二人加入才升级」逻辑——用户确认现状即目标状态）。
11. **码属性**：家庭/家族码一次性（用后即焚）；陌生人码多人次、可设使用上限；默认 7 天有效期（创建时可选）；创建者本人可撤销，家庭/家族码所在空间的**空间管理员**也可撤销。
12. **码格式与分享**：8–10 位无混淆字符随机码；分享渲染为 `…/register?code=XXX`，注册页自动回填。
13. **建码资格**：仅 active 成员；provisional 不可建码。
14. **设置页「邀请码」区块**：查看/创建/撤销我的码 + 填码加入空间（家庭/家族码；陌生人码仅注册场景有效）。

### 并流与兼容
15. **建档/邀请与码系统并存**：既有「帮他人创建账户」流程完整保留。
16. **并流绑定**：建档/邀请撞到已存在的自注册用户名时，转为**绑定请求**——发起人只见「该用户名已被注册」，本人登录后以 PIN + 「这是我」确认，人物挂接既有 user；全程不泄露被绑定方任何档案数据。
17. **冷启动**：OnboardingView 零账号文案改为注册引导；首个注册者即第一个用户；无空间新用户沿用架构 §215「我的家庭」首登引导。
18. **§0.6 owner onboarding link 的 admin-web 签发入口移出本任务**，留作后续「部署方定向邀请」选项；陌生人码已覆盖新家庭进入场景。
19. **UX 包**：LoginView 加注册入口；新增注册视图（含可选邀请码输入，支持 URL 回填）；设置页新增邀请码区块。

## Acceptance Criteria

- [ ] 开关开时，未登录用户可经 LoginView 入口进入注册视图，提交用户名+PIN+显示名后登录进系统；PIN 即刻生效，无强制改密步骤；Profile 为 provisional。
- [ ] 开关关时（`REGISTRATION_ENABLED=false`）：注册端点拒绝（非 2xx），前端无注册入口；系统后台全程无任何注册痕迹。
- [ ] 注册端点有 IP 维度限流；用已占用用户名注册返回与成功路径不可区分枚举信号的统一文案。
- [ ] 注册时填家庭/家族码：注册完成后持码人已是该空间 active 成员（走 pending→active 同一条状态机，有 added_by 审计）；码一次性，二次使用失败。
- [ ] 注册时填陌生人码：注册者获得自己的独立新家庭空间（创建者为 space_admin），归因（码、邀请人）留痕，双方账号之间无任何空间成员关系或档案可见性。
- [ ] 无码注册：进入「我的家庭」空态引导（§215 沿用）。
- [ ] 设置页：active 成员可创建三类码（家庭/家族码绑定其所在空间）、查看我的码、撤销自己创建的码；空间管理员可撤销其空间的他人创建的码；provisional 用户建码被拒。
- [ ] 设置页填码：家庭/家族码走与注册时相同的加入语义；陌生人码在设置页兑换被拒并明确提示。
- [ ] 码过期/撤销/达到上限后：注册与兑换场景均拒绝，文案不泄露码状态细节以外的信息。
- [ ] 建档时目标用户名已存在：流程转为绑定请求，发起人界面仅见「已注册，已发送绑定邀请」；被绑定人确认（PIN + 「这是我」）后人物挂接其既有 user，产生审计事件；确认前发起人看不到对方任何数据。
- [ ] 既有建档/邀请流程回归通过（并存不被破坏）；身份 FSM 三条状态机转换点唯一性不被破坏。
- [ ] 全新部署（零账号）→ 注册第一个账号 → 该用户可自建空间正常使用（冷启动闭环）。
- [ ] 后端 `python -m pytest` 全绿；前端 `npm run test`、`npm run type-check`、`npm run lint` 全绿。

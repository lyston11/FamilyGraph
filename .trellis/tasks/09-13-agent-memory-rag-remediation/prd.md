# 双 Agent RAG 与记忆修复及能力优化

## Goal

让用户能够可靠地保存、找回和核验记忆，让 Assistant 在长会话中保持连续，并准确呈现 Steward 已具备与尚未接入的知识能力。

用户于 2026-09-13 要求创建完整规划包，规划交付后明确回复“执行”。本轮按已审阅方案执行 A～D 修复及 E 的评估职责；可选能力不默认上线。总任务负责审计台账、子任务映射、跨模块验收与最终集成，不作为默认业务代码实施分支。

## Background

当前工作区审计基线为 `b7bd368`，包括当时已有的未提交文件；审计未修改业务代码。事实、原文定位、置信度和复现记录统一保存在 [完整审计台账](research/audit.md) 与 [复现证据](research/evidence.json)。

- Assistant：同会话 user/assistant 文字历史持久化，每 Run 恢复；最新用户原文触发一次 FTS5 RAG 预取。
- Memory：候选经用户确认才成为记忆；普通聊天不会自动入库。来源、确认状态、可见性、敏感等级与生命周期是检索边界。
- Steward：确定性核心加可选的候选、排序、解释批次；持久化进度、去重和冷却，不消费共享 RAG 或私有会话。
- 已有 211 项相关测试通过，但真实接口和离线压缩核验暴露了端到端缺口。这些通过记录不构成修复后验收。

## Requirements

### R-01 可用且可追溯的记忆创建

用户通过已有“新增记忆”与“检索结果保存”入口，应能创建候选、查看原文、选择允许范围、确认保存。手工内容是本人明确提交的来源，不伪造授权文档。检索来源必须重新授权，复制后仍保留来源依赖。接口成功响应须与已提交状态一致；相同操作的安全重试不制造重复候选或记忆。

证据与严重性：MR-01/P1，`MemoryEditorDialog.vue:93` → `memory_rag.py:202` 实测 422；MR-02/P1，`models/memory.py:52` 与 `schemas/memory.py:29` 字段不一致，实测提交后 500 及列表 500。子任务 A 负责具体兼容与来源契约。

### R-02 可测的中文召回与上下文选择

同一条已确认记忆可由合理中文短词、自然问句及有明确前文的追问找回。查询不能以整句原文完全命中为必要条件；没有依据或指代不明确时不得编造查询实体。原有英文短语、权限、来源状态和本地敏感要求不得退化。分块、排名和预算行为可解释、可回归。

证据：MR-03/P1、MR-04/P2、MR-09/P2，`memory_rag.py:415,545,620`；`internal_agent.py:447`。向量库、通用语义理解和开放领域同义推理不作为一期必要条件。

### R-03 长会话连续性

恢复后的合法历史既进入模型上下文，也进入 Pi 用来压缩的同一个会话管理器。压缩请求能看到较早历史的关键事实，压缩后可继续使用这些事实。当前用户消息只发送一次；相同文本、不同消息 ID 均保留。不能通过关闭压缩或静默截断历史掩盖问题。

证据：MR-11/P1，`agent/src/session.ts:377,420`，Pi 0.84.3 离线强制压缩已复现旧历史脱落。真实自动触发频率尚未测量。跨 Run 持久摘要属于 E 的单独设计，不冒充本期已实现能力。

### R-04 索引可恢复且不复活失效内容

RAG 关闭期间确认的合法记忆，在有效开启并由维护流程推进后无需再次确认即可被索引。维护过程须有界、可重启、可重试；撤销、删除、到期、来源失效和已失效版本不得被补建或重建重新激活。稳定有效的来源重试不得改变引用定位。

证据：MR-13/P1，`memory_rag.py:379,926`，实测开启后 0 命中、显式 rebuild 后 1 命中；MR-25/P1，`memory_rag.py:453,929` 的失效状态复活通路为静态确认，待隔离回归。

### R-05 回答来源可核验

回答实际引用的记忆来源应经过可信来源表核验，并在流式消息和刷新后的历史中保留。不得把“检索到”直接标为“回答已引用”；模型编造的引用不得变成有效来源。已有 CitationList、网页引用和事件幂等机制继续复用。

证据：MR-14/P2，`agent/src/events.ts:173,235`、`backend/app/services/agent_events.py:193`、`frontend/src/stores/agent.ts:171`。事件 16 KiB 上限须纳入引用设计。

### R-06 边界、配置与能力说明真实

保留当前部署开关与平台配置的生效语义、Provider 选择和家庭/admin/internal listener 隔离。Memory 关闭时不能保留可提交的“保存为候选”入口。删除、撤销、会话历史、领域称谓与通用长期记忆的含义须清楚，不承诺物理擦除或自动学习。

证据：MR-15、16、17、20；`platform_features.py:38`、`MemoryRagPanel.vue:96`、`memory_rag.py:801`、`terms.py:268`。旧归档文档内相互矛盾的开关优先级不能替代当前代码事实；本任务不顺带改变该策略。

### R-07 验证覆盖真实使用链

每个已复现缺陷都有能先失败后通过的回归。既验证实际 API 与数据库契约，也验证实际 Pi SDK 的本地假模型链；UI mock 只能作为补充。召回集、隐私反例、恢复与索引重放须分别验收。线上启用状态、真实模型质量和运行延迟另留证据，未测不得标通过。

### R-08 后续优化完整登记

主动检索工具、聊天候选提取、聊天保存入口、授权导入、embedding/reranker、全请求预算、跨 Run 摘要、编辑/保留策略、Steward 知识与行为优化均要有目标、输入输出、成本、权限和采用门槛。没有产品授权或收益证据的项目保持延期，不因“像 Agent”而默认上线。

MR-21/22/23/26 等 Steward 附加发现必须区分已有范围限制、异步取舍和待复现故障；全量重建行为投影不得抹掉其他键族的冷却状态。

## Out of scope

- 生产部署、调整线上开关、调用真实模型和不可逆数据处置不包含在本轮默认执行范围；业务修复、隔离 worktree、相关检查与本地提交按子任务推进。
- 一期不默认启用聊天自动提取、不将会话全文入 RAG、不增加任意工具/网络权限。
- 不默认安装向量数据库或外部 embedding 服务；语义检索先评估。
- 不实现跨空间 Steward 发现、自动确认事实、自动代用户发申请或入空间。
- 本任务不接管已有 followups、平台开关、Provider 或家族树成果；后续用户授权的 [称谓闭环](../09-13-steward-kinship-capability-closure/prd.md) 可窄范围修订职责冲突，既有任务状态和独立成果保持不变。
- 不进行主库物理清理；软删除与物理擦除的产品差异在 E 中记录。
- 全请求预算和跨 Run 持久摘要不与 Pi 状态同步修复混为一个已完成事项。

# H：助手增量正文显示协议与交互方案

## 状态与交付目标

planning，**方案任务**。用户要求将全部问题建子任务，不等于选择上线逐字显示。本任务交付可评审的协议、交互、安全与兼容方案；只有明确采用后才另行将实现纳入范围并更新验收。父任务 `09-17-dual-agent-latency-result-integrity`，主会话内联。

目标：准确界定增量显示能减少的等待，解决临时正文、最终答案、取消/失败、引用、重连之间的完整合同，避免直接透传SDK delta。

## 已知事实

`agent/src/events.ts:178`、`agent/test/assistant-delta-gap.test.ts`证明公共assistant正文只在message_end发布，SDK已收到delta时用户仍可能看不到正文。它只证明发布边界，不证明上游首字快，也不排除SSE或渲染延迟。历史最终正文、工具授权、完整历史压缩与引用绑定合同必须保持。

## 需求

| ID | 要求 |
| --- | --- |
| H-R1 | 方案区分首SDK正文、首临时可见正文、完整答案和任务完成，展示改善不宣称推理提速。 |
| H-R2 | 定义run/attempt/message/顺序/epoch、重放去重和最终正文权威替换；断线/刷新/重试不重复、不串消息。 |
| H-R3 | 临时文本不得绕过输出policy guard；thinking、工具参数/结果不当正文，引用/cardIds只随服务端权威结果绑定。 |
| H-R4 | 取消、失租、失败、撤权、切账号/空间有明确临时内容去留和可见状态；不得把部分内容当已验证成功。 |
| H-R5 | 聚合频率、单帧/总缓存上限、背压、滚动/选择/读屏行为明确；复用已有组件与store。 |
| H-R6 | 提供兼容完整消息旧客户端、发布顺序、回退方式与可执行验收计划；不将方案批准等同上线批准。 |

## 依赖与范围

D/F提供可信计时与真实传输基线；可先研究现有边界，最终收益判断等待其证据。无需阻塞C～G可靠性修复发布。若产品决定采用，先扩充本任务实现验收并再评审，后续变更再走F/G同等检查。

不改Provider、thinking、预算、工具副作用或RAG权限，不做通用聊天UI重构。推荐采用安全校验后的有界增量而非裸delta；如果现有guard只能验证完整答案，方案必须保留缓冲或延期，不能以体验为由降低防护。

# B：管家调用结果保全与批次时限一致性

## 1. 状态、来源与依赖

- 父任务：`09-17-dual-agent-latency-result-integrity`；对应父 PRD R2/R3/R5/R6/R7，AC-02～05、07～09。
- 状态 planning。本轮仅文档；用户没有批准编码、测试实现、生产调用或调参。禁止子智能体。
- 实施依赖：先完成父任务共同基线和安全/成本边界冻结，再在本子任务 worktree 实施。与 A 不并行；共享 backend/Provider/SQLite 时严格串行。
- 定义：一个 batch 含多个 attempt；attempt 成功仅表示取得并验证产物，是否适用仍由写回时权限/语义/租约决定。

## 2. 问题

当前 `execute_batch` 串行请求，把返回值存内存 `results`，全部请求结束后才统一保存。若第二笔请求消耗剩余租约，第一笔已返回结果也可能无法保存；恢复器只能把数据库里仍为 `in_flight` 的行记为 `unknown`。

此外，`recover_stuck_batches` 优先把含 unknown 的批次标 failed；`_apply_batch` 遇任一 unknown/failed 也直接终止，不应用其他已成功产物。因此“改成逐笔保存”还不足以完成成果保全。

terminology 同 viewer/root/target/semantic_hash 的 unknown 禁止重发，且判断先于 request_hash 比较；其结果不是简单“下一轮再试”。09-17 两笔 unknown 的上游真实完成状态无法从现有审计还原，不能先改其历史状态。

## 3. 目标

1. 后续慢调用不再使先前已在有效执行权下取得的结果丢失。
2. 独立成功产物可以在同批部分失败时安全消费，不牺牲撤权、证据更新和旧 worker 拒写。
3. 请求总截止、批次租约、保存/应用收尾时间一致，并有界关闭资源。
4. unknown 只表达无法确认结果，不被用来掩盖程序延迟记账；不放开未知请求重放。
5. 成功、空结果、部分失败、授权过期各有真实证据，不承诺每次模型都产出称谓改善。

## 4. 需求

### B-R1 已返回结果及时保全

一笔请求获得结果后，在执行身份仍有效时完成本笔安全审计与校验产物保存，再发下一笔。已保存终态不得被后续请求失败改成 in_flight/unknown，也不得重复计费。DB 写事务不跨网络等待。

若锁等待或租约接管使本笔保存时已无执行权，旧执行者仍拒写；此不可确认窗口必须如实标明，不以“任何结果都必保全”作无法兑现的保证。

### B-R2 部分成功可消费

含 succeeded 与 failed/unknown 的批次，独立且仍通过业务栅栏的成功产物须应用或记录具体不适用原因。同批其他请求失败本身不是拒绝独立产物的理由。

独立性需按 kind/受众/输入验证：candidate 仍只是内部线索；ranking 仍为完整合法排列，不能对残缺元素做部分排列；explanation 只应用当前合法卡片；terminology 按既有 viewer/group/target 语义与抑制规则。共享栅栏失败时可以整批 superseded，不能为“部分成功率”缩小授权检查。

合法空结果也要确认已检查，避免下轮对同语义无限重复。不能伪造非空改善或建议。

### B-R3 恢复幂等与租约安全

进程在一笔审计后、下一笔发送前/中/后、最终应用事务前崩溃时，恢复器分别处理 saved、reserved、in_flight；只用新的 recovery 执行身份消费已保存成果。已终态业务应用与批次完成应具有可重入证明，重复 recovery 不新增模型请求、不重复候选/建议/应用或费用。

旧 owner、旧 attempt、过期 deadline 在发送、审计、应用三个位置均失效；锁等待后重取真实时间，不依赖事务外过期的时间采样。

### B-R4 总时限与资源

单次 HTTP 的总体截止包含连接/发送/headers/body/解析，不能由不断收到小块数据无限延长。下一笔发送前判断剩余时间，给审计与事务收尾预留有界时间。截止后停止网络读取并关闭请求；不允许调用表已终态但后台线程继续占着请求。

未发送请求不标 unknown、不产生实际上游调用计费；已发送且不能确定上游状态保守计费、不自动重发。不要把 connect/read/transport 的所有异常简单归为可重试。

### B-R5 边界不变

沿用 Provider、模型、预算/输出 cap、开启维度、云许可和真实未知去重。四 kind 输入/输出校验、两次 policy/事实 fence、写回 CAS、terms 别名仅 locale/system、个人偏好优先、反馈抑制均保持。

普通 GET 不触发模型；确定性 PFV 不被模型等待阻塞；网络仅在既有有界执行线程和独立 Session 中运行，任何写事务内无外呼。

### B-R6 可观测与兼容

记录每笔真实耗时和安全终态，不因批次尾部丢失已知 latency/usage。区分“已返回未适用”“已发送未知”“未发送”。批次聚合不得把有失败批次伪装成完全成功；读侧需能根据既有 attempt/产物证据识别部分应用，必要的最小新增字段另行落实兼容合同。

存量 unknown 不回填虚构输出、不解锁重试；旧 batch/attempt nullable 字段和终态兼容。原始 prompt/响应只保留既有摘要/长度；新错误日志不得泄露私密内容。

## 5. 验收矩阵

| AC | 场景与必须成立的结果 |
|---|---|
| B-01 | 第一笔成功，第二笔慢至截止：第一笔审计在第二笔开始前已可由独立 Session 读到；不变 unknown；第二笔分类与费用真实 |
| B-02 | 第一笔成功，第二笔失败或 unknown：符合当前授权的独立成果被应用；批次仍可见失败事实，不把结果全丢弃 |
| B-03 | 合法空 items 与其他 unknown 混合：已检查状态正确，同语义不反复发送；不产生虚构称谓改善 |
| B-04 | 保存后崩溃，恢复取得新 lease：已有成果安全应用；旧执行者拒写；重复恢复无额外网络和业务写入 |
| B-05 | in_flight 无结果：仍 unknown、保守计费、同语义不重发；只改 prompt/request_hash/新 job 不绕过 |
| B-06 | reserved 未发送/截止前时间不足：没有实际 HTTP；不当 unknown；保留已有未发送失败/重试策略，次数有界 |
| B-07 | 间隔小于 read timeout、总时长大于总体截止的慢 chunk：仍在总体截止与明确容差内终止并关闭连接，无资源增长 |
| B-08 | 撤权、禁用、更换 Provider、事实/卡片/语义变化、反馈抑制、别名词表越界：均不能应用旧产物，错误原因脱敏 |
| B-09 | 旧 owner/attempt、过期或锁等待跨 deadline：发送/审计/应用均不越权；覆盖真实事务而非仅 mock 判断 |
| B-10 | 四 kind、预算不足/usage 缺失、队列取消、并发 recovery、旧行兼容回归通过；无 DB 事务跨网络 |
| B-11 | 隔离真实小样本按批准上限验证传输/保存/应用分项；无合法改善可记录，但不能用空结果冒充改善 |
| B-12 | 相关门禁、观测 evidence、Spec 更新、部署最小检查满足；必需验收缺口未关闭则不归档 |

## 6. 非目标

不提升并发、不自动扩大超时/租约、不换模型或开新云许可；不为历史 unknown 添加重试入口；不重写整体队列；不保证上游更快。结果保全成功只证明减少系统自身丢失，不代替父任务的端到端速度比较。

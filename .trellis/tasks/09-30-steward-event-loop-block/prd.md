# Steward 长 run 请求饥饿与心跳超时

## 目标

长 Steward run 执行多工具调用时，心跳、lease、health 仍能得到及时响应，不因共享资源饥饿而失租。限定开发环境；线上由用户手动发布。

## 事实与证据边界

- 历史记录存在 32–130s API 访问日志空档，以及 sidecar 请求超时、run 106 租约不再推进后失租。日志空档不等同于事件循环阻塞。
- 维护日志间隔曾达 224s，但 `maintenance_loop` 仅在 counters 非零时写日志，不能据此计算维护停顿时长。
- 历史探针报告 health 单次 65,830ms，并保存了单次栈摘录：若干 AnyIO worker 位于 `acquire_run_writer`/SQLAlchemy `do_execute`，另有连接初始化栈。详见 `research/evidence/r0-blocking-stack.md`。
- MainThread 的 `_read_from_self` 是处理事件循环唤醒，不是 selector 等待栈；单点采样不能证明此前整个慢请求期间 loop 空闲。
- 未保存足以确认采样与慢请求重叠的完整时间边界，未测当时 AnyIO borrowed/total tokens、连接池 checkout/wait、写事务持有者。因此“40 个线程被耗尽”“30s pool_timeout 导致全部静默”仍是候选机制，AC-0 未完成。
- 历史计数称一轮 21–26 个工具调用；不同材料对 run 189 写过 24/26，轮内总数不等于同时在途峰值，需从原始事件重新计算。
- 小型受控流探针测得 `_refresh_run_gate` 约 3µs、400 chunk 累计 lag 8.3ms。它未复现长暂停，不能据此排除真实负载下所有同步 DB/连接等待。
- 源码确认：`agent_tools.execute` 在 fence 后还做准入 CAS、`AgentToolCall` 幂等占位，提交后 dispatch，最后持久化结果和审计。业务只读不等于整个执行路径无写操作。

## 需求

### R0 定位先于生产修复

在真实慢请求尚未完成时采集栈与资源占用，或在隔离文件 SQLite + 真实 HTTP 路径受控复现，区分事件循环延迟、AnyIO 排队、连接等待、写锁等待和持有时间。指出导致心跳超时的实际阶段，解释量级；不可用单点栈宣称完整因果链已确证。

### R1 长 run 不得耗尽请求处理能力

多工具、多个 run 的负载必须有界。等待工具执行机会不得占用共享工作线程或数据库连接。不能通过放宽 sidecar 超时/租约来掩盖；若存在异常长的事务或连接占用，应针对持有者修复，限流不能替代这一定位。

### R2 其他端点持续可服务

在明确且可复现的压力场景中，心跳、lease、health、context、settle 延迟有界；不能只让 health 返回而心跳仍失效。有限工具批次必须最终完成，不能靠拒绝全部工具取得通过。

### R2b 可诊断

超阈值日志区分实际测量到的排队、连接/事务阶段，不把总响应时间标为线程池耗尽。字段仅含安全标识、时长、计数，不含正文、token、SQL 参数。诊断不依赖同一被占满的执行队列。

### R3 合同不变

- 保留 fence 的写锁与检查集、取消/撤权先后顺序、准入 CAS、幂等和审计。排队后进入执行仍重新验证有效身份、租约和权限。
- 已准入调用按既有完成合同处理；不得要求取消后抹掉已发生执行或审计。
- 保留 per-chunk run gate、egress 恰好一次审计、上游 4xx 状态码与不可重试合同，以及流中中断分类。
- 不改变 wire 协议、不新增端点、不改 sidecar、不改 schema。

## 验收

| ID | 可观察结果 |
|---|---|
| AC-0 | 同一慢请求窗口的栈/资源数据或等价受控复现，定位等待阶段与持有者；当前未完成 |
| AC-1 | 相同负载修复前后对比，心跳/health 延迟下降且工具批次正常收敛；记录连接与线程占用 |
| AC-2 | 同 run 多工具、多个 run 并发时心跳成功；测试负载、并发上限、时间阈值在修复前固定，不能靠改大超时通过 |
| AC-3 | 开发环境至少一次完整长 run，主动探针无 >30s 停顿、心跳无超时、无因饥饿产生的 expired |
| AC-4 | fence、排队期间取消/撤权/失租、幂等、Provider 合同回归通过 |
| AC-5 | backend 全量 pytest / ruff / mypy 通过；未改 agent/frontend 时说明未运行原因 |
| AC-6 | 过载日志能区分已测量的等待阶段，且无敏感数据 |

## 不在范围

全局调大线程池/连接池、无证据缩短 pool_timeout、删授权写锁、放宽租约、改 sidecar、独立服务拆分、回填历史 expired、线上操作。

# Gate 5 缺口闭合：sequence 修复必要性 + backup/restore 演练

## 1. sequence 修复 —— 已证明必要性（负向用例）

初版用 plain `int` 主键，`setval` 路径从未执行。本版改用
`GENERATED BY DEFAULT AS IDENTITY`（PostgreSQL 惯用），并做**负向验证**：

```
[OK ] 不修复 sequence -> 主键冲突（符合预期）
[OK ] 修复 sequence 后插入 -> 新 id=6（期望 6）
```

**为什么负向用例是必需的**：只测「修复后能插入」无法证明修复是必要的
（不修复也可能碰巧通过）。必须先证明**不修复会失败**，才能说明
`setval(pg_get_serial_sequence(...), max(id))` 是导入流程的必需步骤。

真实迁移的含义：导入保留原 ID 后，identity/sequence 仍停在初始值，
**第一次新插入就会撞已有主键**。这不是理论风险，是本次实测。

## 仍为原型/未覆盖（诚实声明）

1. **合成数据**：`sq_items` 是最小模型，不是真实 88 表 schema。
2. **未测 RPO/RTO**：没有测量大表耗时，也没有做时间点恢复（PITR）。
3. **未测跨表 FK 顺序导入**：单表无 FK 依赖。
4. **未测大表分批与断点重试**。
5. **未测真实 RAG revision/citation 与 egress 一次一审计的对账**。
6. `pg_dump`/`pg_restore` 的完整往返（含 `pg_restore -Fc` 二进制格式）未测，
   本次用 SQL 文本格式。

语义与负向验证。**不是**真实历史库的迁移演练。

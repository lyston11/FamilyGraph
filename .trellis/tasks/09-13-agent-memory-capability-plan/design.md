# Design：能力评估与准入方案

## 1. 评估记录合同

每个 E-O 产出一条记录：问题/用户场景、当前路径、候选方案、输入输出、授权边界、实验集/版本/命令、结果、成本、采用门槛、决定及下一步所有者。状态只取“设计待评估 / 已评估采用 / 已评估保留现状 / 明确延期”；没有实验不能记“已评估”。

能力状态分四列：实现符号是否存在、生产调用是否接通、当前环境/平台/空间是否生效、本轮是否验证。现有 deployment hard-off 与 DB AND 不改变；引用之前开关任务时同时保留修改前零调用与修改后成功的历史，不推出今天线上状态。

默认所有新增能力保持设计待评估。离线协议可在本任务 research 内实现合成 harness；生产源码/迁移/线上配置不属于 E 直接所有权。

## 2. E-O1：主动检索

输入为当前已授权 Run 的 query 与有限定位条件；账户/空间/consumer/Provider 从服务端身份派生，模型不能指定任意用户/SQL。输出复用 B 的 ContextBuild/来源句柄、有限内容与排除原因。工具调用必须有后端准入、调用次数/时长/输出预算、取消与 lease 失效处理。

建议首个比较方案每 Run 最多额外 2 次检索，不允许递归、无界分页或通过工具直连数据库。由受控预算判定是否调用；记忆内容保持 untrusted_data，不从检索文本动态注册工具。

在至少包含追问、需要第二步实体信息和无需检索的合成任务集中，对比 B 改善后的一次预取。采用门槛是冻结扩展集召回/答案来源覆盖有净增益，权限反例零越界，额外调用和 p95 延迟在事先确认的成本上限内；上限必须在跑实验前记入记录，不能看到结果后移动。若一次预取已足够则延期。

## 3. E-O2/O3：显式保存与自动候选

显式入口第一候选是“从我的这条输入整理记忆”，沿 A 的原始 user 消息来源创建 pending 候选，用户核对原话/摘要/用途/范围/保留期后确认。按钮成功只表示待确认已创建；没有确认和 Memory ID 就不显示“已永久记住”。

Assistant/工具/RAG 派生回答不能走 A 的独立消息快照。若产品要保存回答，先让来源图可验证：正文片段与 cited sources 绑定、依赖失效传播、混合自述与检索内容的范围规则；不能简单把整段标 manual。存量 legacy 不自动升级。

自动提取是独立默认关闭选项；输入范围、敏感内容外发与保留期需明确。输出仅有上限内候选及原始 span/source ID，不直接确认、不新建结构事实。按会话/message/span 和规范化候选去重，重试/取消不重复；抽取失败保留聊天正常完成，不伪装记忆成功。

评估集同时包含明确偏好、否定/更正、玩笑、引用他人、临时安排、混合来源和重复消息。先测候选精确率、漏检、用户确认负担与更正一致性；自动方案必须有可关闭/撤销/解释入口，未证明价值则只交付显式入口方案。

## 4. E-O4：授权文档入库

拟议链：受认证上传 → 格式/大小/内容校验 → 受控解析 → 来源权属与可见范围确认 → 原文版本/可定位片段 → RAG 文档物化 → B 检索/引用 → 源撤销/更新经 D 失效。

先评估纯文本/Markdown 等可控格式；PDF/Office/OCR 和远程 URL 是额外解析及网络范围，不因底层 service 支持字符串就默认提供。解析输出是数据，不能成为 system 指令。文件名/MIME/客户端 scope 不构成授权；附件下载继续走后端授权。

文档更新产生来源 revision，撤销影响所有派生候选/记忆/索引。测试同名文件、版本替换、分段定位、无权用户、解析失败重试和撤销。不得把家庭全部 story/profile 自动导入；要逐个确认生产数据来源与授权入口。

## 5. E-O5：语义检索/重排

候选至少包含：B 的词法基线、可本地运行 embedding 的混合召回、在有限候选上的重排。先使用独立冻结扩展集中的同义问法、别名、跨句事实和干扰资料；核心集不能退化。

报告 Recall@5、MRR、无关命中、引用有效率、p50/p95 延迟、索引大小、更新/删除传播时间、每千查询调用/费用与本地资源。阈值在实验前冻结，不能仅用“过年”一个样本证明值得上向量库。

high/local_required 或来源限制不能因 embedding/rerank 外发而绕过现有政策。向量投影同样有来源 revision、删除和重建语义，不能成为无法撤销的第二份私有知识库。净收益不足、运维成本不接受或本地路径不达标时保持词法方案。

## 6. E-O6/O7：完整上下文预算与跨 Run 摘要

预算输入必须覆盖 system/policy、允许历史、当前 user、RAG 包装、工具定义与结果、provider 格式开销及输出 reserve；以本轮 Provider/model 快照的窗口为界。未知窗口不能猜为无限，tokenizer 缺失使用经验证的保守估算。

流程：估算完整待发请求 → 可追溯压缩/检索裁减 → 新输入与工具结果加入后再次复核 → 有界调用或明确超限失败。Pi pre-prompt 压缩发生在加入新 user/RAG 前，不能只测历史就称总预算正确。错误输出应让用户知道可缩短输入/拆分操作，不静默删掉较早事实后宣称记得。

跨 Run 摘要独立建模：account/space/session、covered_through_message_id、source message ID 集/游标、summary_version、policy/provider 兼容版本、provenance 依赖、失效状态和生成幂等键。只重放摘要覆盖范围后的尾部，同 ID 不重复，跨 session 不复用。

不能直接持久化 Pi compact 产物，因为其中可能含本轮 RAG/工具资料。候选方案须选择：仅总结获权的原始对话并剥离派生内容，或完整保留来源依赖且每次重验；两者均需证明做得到，不能仅凭文字过滤假定已剥离。来源撤销、成员资格变化、消息修改/删除、policy 变更时摘要可失效并从合法源重建。未选定来源策略时延期持久摘要，保留 C 的局部一致性修复。

## 7. E-O8/O9：编辑、范围与保留

编辑已确认记忆采用新 revision/新确认记录，保留原来源与变更关系；扩大共享或降低敏感度不能脱离来源限制。对原始来源失效的副本，不允许通过修改正文/转 manual 绕过。索引原子换版，旧引用不改指。

保留政策分别列明：候选/Memory、RAG/FTS/embedding 投影、聊天回答/事件/摘要、日志、备份和已外发 Provider 内容。软删除/撤销只保证后续受控读取和召回失效，不能声称已抹除备份或已发内容。

物理清理方案需有对象/保留期/法定或产品审计要求、备份影响、可逆试运行报告和不可逆执行步骤；本次不选择保留天数、不执行删除。产品先决定是否需要历史展示遮罩与物理擦除，以及谁能发起。

## 8. E-O10：Steward 共享知识交接

实际实现所有者是 [既有能力后续任务](../09-11-steward-capability-followups/prd.md)。本任务给出 A/B/D 的 service 合同、来源失效/引用规则及评估案例；不创建另一条实现支线。

至少比较六类合成场景：已确认共享家事、有冲突的共享摘要、过期/已撤销资料、只有 private 来源、需本地 Provider 的来源、没有资料时保持确定性产出。shared RAG 只能用于有证据的辅助解释/候选，不推翻确定性 DerivedFact、不跨空间发现，不读取私人会话。

Steward 仍用专属 job/consumer 身份，不能伪造 generic AgentRun 来通过 ContextBuilder。模型输出仍经现有 schema、evidence 校验与候选审核；共享上下文来源不足就保留原路径。个性化文案/地区内容等已登记议题仍由原任务决定。

## 9. E-O11：反馈与行为投影

先比较当前确定性排序与现有薄输入模型排序；明确哪些反馈信号能合理改善 card relevance，而非提供整个聊天历史。候选特征以白名单结构、有限时间窗、授权 scope 和过期规则定义，模型响应不能替代业务状态裁决。

TermRegistry 是现有称谓持久化真源；Assistant record_term_usage 的明确同意约束保留。correction_preference/term_usage 投影只有在找到实际消费者并明确用途后才启用，不复制第二套称谓。

MR-26 复现协议：同账户/空间同时造 card 冷却、term/correction 投影及 family_recommendations 的独立冷却键；用真实 rebuild helper 回放允许事件，再比较非目标键是否原样保留。当前 helper 无生产调用，此实验是条件性风险验证。最小修复方案只删除/重建自己拥有的键族，同一事件集重复回放结果一致，保留其他键；不顺带新增事件水位，增量回放另列可选优化。若没有消费者，继续不接 maintenance。

## 10. E-O12：候选新证据、冷却与异步可见性

MR-23 的重现必须从 fake candidate transport 进入：core/assist 第一次产生结构候选 → 后续 core 投影为 Suggestion → 用户 dismissed → 添加相关新证据 → 再跑同结构模型输出 → 后续 core 检查是否产生新的证据版本。另加只有无关事实变化、重复回放和无新证据三组对照，禁止只直接调用 upsert。

合成 fixture 在实验前独立标注 expected_support_fact_ids，作为判定相关证据的基准，不注入生产候选 digest。当前候选输出仅含关系类型/端点（steward_guard.py:254），Suggestion 快照使用本次全部 facts（steward_suggestions.py:286,329），尚无“相关证据归因”能力，设计不能假定已经存在。逐阶段记录 job/batch ID、辅助开关是否生效及是否实际调用、candidate ID/digest、Suggestion ID/evidence_hash/status；据此区分未调用、结构去重拦截、尚未投影和证据未更新。

拟议最小模型是“稳定结构身份 + 相关证据版本”：结构为 kind/端点，证据版本只涵盖真正支撑该候选的 source/revision/validation contract，不能用整空间 hash。相同结构/相同证据重放不重新提醒；相关新证据形成可审计的新候选版本并 supersede 旧建议，是否提示遵循已批准的 UX。先测生产链是否确实阻断，再定字段与迁移，不预宣称故障已修。

Suggestion.cooldown_until 当前未进入时间过滤；ActionCard 已有生产写入/读取路径，在 BEHAVIOR_PROJECTION_ENABLED 开启时生效（steward.py:228,245），本轮未验证线上开关。默认保持同证据 dismissed；“过几天自动再出现”是独立产品决定，若未来采用，应一次统一 job、list、通知和投影，冻结时钟测试边界/时区/重复提醒，不能只改列表条件。

core 完成后 assist 才落候选、下一 core 才投影是当前最终一致性取舍。先测可见延迟与用户期望；确需优化时用有限、幂等、只执行投影的 followup，不再次安排相同模型批次形成循环。该延迟优化与结构去重缺口分别验收。

## 11. 所有权与退出条件

E 只拥有本任务研究记录、隔离合成评估材料和交接文档。采用任何生产补丁时先明确一个实施所有者/子任务与独立 worktree；MR-23/26 的优先级不会因 E 默认 P3 被降低，研究确认后分别以 P2 排入对应 Steward 修复，不和 shared RAG 混成必需的大重构。

评估失败、证据不足或产品选择未定时，可以交付明确延期及重新评估触发条件；不得打勾为能力已完成。线上模型质量、费用与运行开关需要独立证据，本轮不提供推断的数值。

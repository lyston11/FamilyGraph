## 修复需求

下列 R-01～R-09 是待执行修复的目标，不表示已实现。

### R-01 过期执行者不能作用于新执行

Run 被重新领取后，旧执行者不能追加回答、续租、结算、执行工具、取得新上下文或通过新的模型请求准入。请求入口成功鉴权不能替代实际读写时的有效身份核验。合法丢响应重试与取消优先级保持明确。

对应 B-I01、B-I05、B-I10；一期修复优先级 P1。

### R-02 引用始终指向实际使用的原片段

认证引用必须同时证明本轮纳入、当前执行绑定、原片段存在且内容/版本一致、当前来源可读。旧索引版本的合法原片段可继续读取；原片段不存在或发生冲突时明确不可用，不改指向新片段。

对应 B-I02、D-I01、D-I02、D-I06、D-I08。

### R-03 各读取出口使用一致的可信引用

历史、SSE/重连、固定补取和下一轮内部历史均不能输出未认证或已失权的结构化引用。sidecar 自报的来源元数据不能变成可信引用。不可用来源只返回允许的数量提示；原正文和网页引用遵循既有保留合同，不承诺物理擦除。合法无引用旧消息继续工作。

对应 B-I03、B-I04、B-I09、B-I10。

### R-04 上下文重取与事件重试可解释

同一执行的并发 context 重取应返回同一合法构建或明确失效，不返回唯一键 500。政策或来源已使构建失效时，不能在同一执行重新生成或恢复为有效。事件同请求重放保持原提交；异参、错构建与错执行不得被当成同一次提交。

对应 B-I01、B-I05、B-I10。总事件的 16 KiB 既有上限和固定授权补取合同保留，不以截断正文换取引用空间。

### R-05 检索能找回合法资料且遵守实际预算

真实 Assistant 路径使用与记录一致的 RAG 子预算，包含材料包装开销。被二次授权排除的前排结果不能无声挤掉预算内的合法目标。只有同会话前文中唯一、明确的锚点才用于追问；歧义/无前文不猜实体、不扩大权限。

对应 B-I06、B-I07、B-I08。保留已验证的中文短词、受控别名、句段分块与英文行为；不把局部预算称为全请求预算。

### R-06 索引身份与内容稳定

同源同内容版本只有一份规范投影，并发重试不产生重复。相同版本、相同引用定位的内容不可被原地覆盖；预先存在的冲突块不能成为活动版本。存量重复和版本镜像冲突须先报告并阻断，不能静默删重。

对应 D-I01、D-I02；治理报告只包含授权元数据。

### R-07 维护批次具有真实租约和事务边界

旧执行者不能回退游标、轮次、策略或活动版本。失租或最终验证失败时，该批次的物化、失败登记和进度全部回滚。关闭开关后不能继续提交新的补建/换版结果。每轮处理固定有限集合，使持续新增数据不饿死后来恢复的低 ID 来源。

对应 D-I03、D-I04、D-I05、D-I09。RAG-only 与平台晚开启的正面行为应保留；不借用 Steward 模型职责。

### R-08 换版、修复和回滚不破坏来源依赖

新活动版本可被检索，普通维护不能把它改回旧版。缺块或缺失 FTS 投影应被识别并恢复/报告，而不是误报已完整。FTS 修复遵守来源合法性。降级不能删除仍被保存记忆或历史引用依赖的片段；无法保持数据时在任何破坏动作前明确拒绝。

对应 D-I05～D-I10。来源整体失效与某位读者暂时失权分别处理。

### R-09 能力边界与交付状态真实

原 MR-01～MR-26 全部保留责任和处置；未接线或待选择的主动检索、自动候选、导入、混合检索、全请求预算、持久摘要、编辑/保留策略及 Steward 反馈不冒称已交付。MR-23/MR-26 的生产修复继续归已有独立规划包，不在此重复实施。

对应 [完整覆盖与优化路线](research/coverage-and-roadmap.md)。父验收未闭合项保持未完成，历史检查通过、规划完成、提交完成和集成验收分别记录。

# D：助手真实阶段计时与重试统计修复

## 状态与目标

planning；本轮仅授权规划，主会话内联。父任务 `09-17-dual-agent-latency-result-integrity`。目标是让排队、准备、模型/工具、重试、压缩、持久化与显示指标具有可解释来源，历史无法还原的阶段明确未知。

## 已确认缺陷

基线 `d8d3668`：`agent/src/worker.ts:163` 先获取 context/create session，再由 SDK `agent_start` 生成 run.started；`:282` 启动批量 flusher。`backend/app/services/agent_events.py` 的 created_at 是入库时刻。合成工具约125ms，同批持久化仅相差1.301ms。

`backend/app/api/admin_agent_latency.py:184`、`:234`：一次失败后成功、失败耗尽不形成正确重试计数/窗口；从事件分组出发使零事件 run 漏分母。工具调用但无正文的 turn 缺 model 样本；压缩无独立分段。源码支持持久事件间隔，不能支持“精确执行耗时/排除工具和显示瓶颈”。

## 需求

| ID | 要求 |
| --- | --- |
| D-R1 | 每个指标声明 source、语义版本、样本范围及缺失/未发生/删失；区分真实执行时长和持久事件间隔，不把 first_text 当首 token/页面可见。 |
| D-R2 | 新运行记录首次 lease、context/session 准备、每轮生成、工具、压缩、正文完成、事件保存与结算的最小安全证据；不能由 heartbeat 推算首次 lease。浏览器收到/渲染由 F 的合成测量补证。 |
| D-R3 | 计数以全部符合窗口条件的 run 为分母；失败、取消、无开始、无事件均保留。重试“存在/次数”和“可测耗时”分开，终端失败段不丢。 |
| D-R4 | Provider 请求证据可关联 run/attempt/turn/request/retry 层；历史只有 run 归属的记录不得强行分配轮次。错误审计生产由 E 负责，D 负责协议与聚合消费。 |
| D-R5 | 不记录 prompt、正文、thinking、工具结果或凭据；观测不产生模型请求、不增大公开事件敏感面、不改终态/取消/引用语义。 |

| ID | 可观察结果 |

## 依赖、非目标

C 后串行推进，先冻结与 E 共用的最小请求元数据合同；D 不修改重试策略，E 不重新定义聚合口径。F 验证全链，G 提供运行版本证据。无需等待 H 的 delta 决策。

不建完整 trace 平台，不写通用监控框架，不改模型档位，不补历史虚构时间，不宣称 `model_turn - retry下界` 等于纯推理。浏览器测量只用合成数据，不新增用户行为采集。落库/协议形状在设计技术门确认后才能实施。

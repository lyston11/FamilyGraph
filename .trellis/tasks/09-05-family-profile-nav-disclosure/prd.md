# 家庭端导航/资料编辑/披露策略修复与种子补全 PRD

## 背景（grilling 对齐 2026-09-05，用户确认"都按推荐"）

用户实测家庭端暴露五项体验问题，定性：返回导航（1 项 bug + 1 项设计偏差）、资料编辑
前端缺口、家族树种子缺口、高敏感披露策略为既定合同但用户决策放开。

## 需求

### R1 上下文感知返回导航（问题 1/3）
- 成员资料页（/people/:id）返回按钮：从家庭卡进入显示「返回家庭卡」、从家族树进入显示
  「返回家族树」，点击回来源页；无来源 state 时兜底家庭卡。
- 设置页返回按钮：修复文案「← 家庭空间」实际跳家族树的 bug → 跳家庭卡（route home）。
- 进入路径携带来源 state：HouseholdCardView.openMember 与 FamilyTreeView.onNodeSelect。

### R2 基础资料编辑表单（问题 2）
- SettingsView 个人资料区新增：性别（男/女/不详）、出生日期、逝世日期（可选）、简介
  （≤2000 字），经 PATCH /members/{self} 提交（后端 MemberUpdateRequest 已支持）。
- 保留既有「修改名字」。保存成功有反馈；出生日期空值走 ''⇄null 映射（NDatePicker 红线）。

### R3 种子补 lineage 家族空间（问题 4）
- dev_seed 新增 lineage 空间「王氏家族」，6 名成员全部挂入（王德海 space_admin）；
- 成员补结构化出生日期（王远山 1940/王德海 1965/周秀英 1967/王建军 1990/王小雨 1993/
  王小虎 2018——王小虎为未成年人，顺带演示未成年保护 overlay）；
- 家庭卡/家族树全流程可演示：家庭卡（household）→ 返回 → 家族树（lineage）。

### R4 高敏感披露策略放开（问题 5，用户拍板 Q4=b）
- 后端披露合同变更：health/address/school/contact/private_notes 五类允许**本人**显式开启
  （全局与空间级），不再"恒不落行"；
- 约束：未成年人（is_minor）对高敏感类别的开启请求返回 422（未成年人始终最小披露）；
- 高敏感披露变更必须写审计（audit_log，action 含 high_risk 语义）；
- 默认仍为关闭；可见性行为不变（高敏感档案内容列本就未落库，策略放开为合同层面）。

### R5 前端披露矩阵放开（问题 5 UI）
- DisclosureMatrix 高敏感开关对成年人启用；开启时弹强确认 Modal（后果文案：开启后
  对应范围成员可见、可随时关闭、未成年人档案不受此影响），确认后才改草稿；
- 文案更新：删除"恒不公开"表述，改为"默认关闭，可由本人开启（需二次确认）；未成年人
  档案始终按最小披露遮蔽"。

### R6 种子成员互见（问题 1 连带）
- 种子为 6 名成员设置基础五类（头像/相册/生卒/简介/链接附件）全局披露开放，使成员卡
  点开有资料；高敏感五类保持关闭（Q4=b 只是"可开"，默认不开）。

### R7 文档同步
- docs/DEV-DATA-SEEDING.md §5 更新：lineage 空间、出生日期、披露默认值、未成年成员说明。

## 红线
1. 隐私合同：披露变更仅限本人（custody edit 权限不变）；未成年人保护不弱化；
2. 空间模型：家庭卡=household、家族树=lineage 不合并（Q3=a）；
3. 测试守卫：既有 data-test 契约与测试语义保持，新增行为必须有测试；
4. 颜色/组件红线（frontend spec）与门禁全绿。

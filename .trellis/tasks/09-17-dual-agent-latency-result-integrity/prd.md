# 双 Agent 响应延迟与管家调用结果保全

## 1. 状态与授权

- 状态：**planning，规划文档待用户审阅；尚未批准实现**。
- 用户于 2026-09-17 反馈“无论助手 agent 还是管家 agent 响应都非常慢”，随后明确“确认并创建，需要写详细 prd 等，但先不执行写代码”。
- 本轮允许：建立任务树、读取本地设计/源码/历史证据、撰写规划。禁止：业务代码/测试实现、`task.py start`、部署变更、服务重启、真实模型压测、生产数据修改。
- 后续仍由主会话直接处理，不使用子智能体。父任务承担共同基线与集成验收，不作为跨模块并行开发许可。

## 2. 用户目标

让用户知道助手和管家究竟慢在哪里，并消除系统自身造成的不必要等待或结果丢失。助手应准确区分排队、模型生成、工具执行与页面收到正文；管家不应因同批后续慢调用而丢失先前已取得的合法结果。不能通过降低答案质量、绕过权限或增加不可控调用费用来制造“变快”。

本任务分别报告三个结果：响应时间、结果可靠性、等待期间的反馈。三者不能互相替代；改提示文案不等于模型变快，真实发送不等于合法结果已被应用。

## 5. 需求

### R1 分段定位与可对比基线（父任务 + A/B）

分别衡量：助手提交→入队→lease→上下文就绪→每次 Provider 请求→首可见正文/消息完成→工具调用→结算→页面可见；管家触发→扫描/入队→确定性发布→assist 注册/租赁→每笔发送/完成/保存→校验应用→用户 API 消费。

记录阶段缺失、未知、未发生的区别。耗时需关联同一 run/attempt 或 batch/call；交叠阶段不可简单相加，重试和工具轮次不可合并成一次模型耗时。历史数据无法补齐的字段为空并标明未知，不倒推或伪造。

### R2 保全管家已完成的独立调用（B）

在有效执行身份、预算和授权下取得的调用结果，不因后续调用慢/失败而退化为“从未确认结果”。已合法保存且仍适用的独立结果，在同批另一调用 unknown 时仍须被消费或给出具体不可应用原因；不能仅因批次 failed 而永久遗留。

失租旧执行者不得继续记账或写投影；保存成功并不等于获准应用。校验失败、授权变化和语义过期仍不得写业务结果。

### R3 总时限、租约与恢复一致（B）

建立可验证的总请求截止与收尾时间边界；不得依赖“每次 read 超时”冒充总时限。时间不足的后续调用不发送，未发送不能记 unknown 或上游实际费用。崩溃/取消/租约接管后资源应有界释放，不得累积仍在执行的后台请求。

正常结束、无效输出、明确未发送失败、已发送结果未知分别记录；真实 unknown 继续保守计费且不自动重放。

### R4 助手等待与性能归因（A）

回答“多久开始执行、多久得到正文、多久显示、多久完成、哪一阶段主导”。复用已有排队/生成提示，先检查真实路径再改。若仅存在展示等待，应把降低首次可见延迟的收益与模型推理时间分开。

对已证明的程序性额外等待提出最小修复并验证；若主要瓶颈是上游且现配置无法消除，交付测量与可审阅选择，不把未变快的系统宣称为优化完成。新增逐字展示属于公开事件合同/UX 变更，须在设计评审中明确选择后才能实施。

### R5 成本、质量与安全保持

沿用当前 Provider/协议/模型/推理设置、预算、owner 云同意和空间隔离。不得因提速跳过工具授权、事实校验、合法称谓词表、RAG 引用绑定、首发/写回栅栏或 SDK 自动压缩。

不得通过 recent-N 截断、删除历史、隐藏错误/工具阶段、增加无限并发/重试来通过验收。unknown 不自动重试是当前合同；本任务先修可靠性，不默认为历史 unknown 提供重发许可。

### R6 可观测性最小化

优先既有事件、调用审计、只读延迟 API；缺失证据时才增加最小必要的阶段元数据。仅保留 ID、时间/时长、状态、安全错误码、次数、长度和获准预算指标；不记录 prompt、回复正文、thinking、工具结果、姓名、密钥或 token。

新增指标不产生额外模型调用，不明显增加写锁占用；保留 source/版本/样本数以及超时删失说明。

### R7 运维与历史记录

新证据纠正旧归因，不改写历史调用终态或伪造 latency。配置与服务版本以实施时加载部署 env 后核验为准。本轮不运行生产探针；后续真实合成调用须先确定上限、隔离 DATA_DIR 和授权范围。生产观测优先正常后台作业与已获授权用户交互。

### R8 完成判定

代码验证、真实链路、实际提速、结果应用、生产配置是独立验收项。规划文档完成不意味着任务完成；实现后仍有必需验收阻塞时保留未完成，不因写了一份“阻塞说明”自动归档 completed。

## 7. 非目标与需另行决定的选项

- 不重写 Agent 框架、不合并助手与管家 runtime，不扩大长期记忆/RAG 能力。
- 不新增大规模监控平台、模型跑分平台或管理控制台。
- 不自动改模型/推理档位/并发/预算/生产超时，不把增大超时称为提速。
- 不自动重发存量 unknown，不篡改语义 hash、prompt 版本或 generation 绕过去重。
- 流式正文 UX、显式重试入口、上游幂等键策略、调参/换模型属于证据后的选项，未被本轮授权。

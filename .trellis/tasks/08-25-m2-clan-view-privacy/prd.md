# M2 家族视图、可见性基线与连接确认流

> 权威上下文：[.trellis/HANDOFF.md](../../HANDOFF.md)。已确认决策视为锁定。

## Goal

打通"小家庭 → 大家族"：家庭空间相连涌现家族空间，树形大图呈现；建立**服务端强制**的可见性基线，保证远房亲属只见卡片摘要、隐私字段不泄露。出口标准：**两家人连起来且隐私不泄露（API 层可验证）**。

## Background（锁定决策引用）

- U3：家庭空间 ⇄ 家族空间按钮切换，缩放过渡动画。
- U4：家族空间非实体；跨家族互不可见（暂定）。
- U5 可见性基线：家族视图中非同家庭空间者只见卡片摘要（名字/称谓/世代角标）；照片、生卒详情、备注、附件等隐私字段一律遮罩；搜索遵循同一基线。
- D4/D8：连接确认流与断连规则已在 M1 建立数据基础，本阶段补全申请入口与体验。

## Requirements

### 家族空间视图
- 定义：从我的任一活跃空间出发，沿 active 关系边连通扩展可达的所有 space_members 并集所构成的视图；不同连通分量互不可见。
- 树形大图渲染（d3-hierarchy + Vue Flow）：节点 = 人，支持缩放/平移/分支折叠（默认展开深度见开放问题 #5，默认 2 层）。
- 与家庭空间的切换：顶部按钮 + 缩放过渡动画（视觉上"拉远看到大家族"）。
- 远房成员卡片 = 摘要态：名字、称谓标签、世代角标、"申请进入 TA 的家庭空间"按钮。

### 可见性基线（服务端强制）
- 后端收敛为单一 `visibility.py` 过滤模块：所有对外返回用户数据的接口（档案详情、图查询 `/api/graph/*`、搜索）统一过此模块。
- 规则：
  - 同一活跃家庭空间成员 或 与我有 active 关系者 → 完整数据（仍受 D5 编辑权约束）。
  - 仅同连通分量可达 → 摘要字段集 {id, name, 称谓标签, 世代, 头像占位}；其余字段返回遮罩标记而非省略（前端统一渲染锁样式）。
  - 不同连通分量 → 图查询中根本不返回该节点（不可见 ≠ 遮罩）。
- 搜索接口复用同一模块：遮罩对象可被搜到名字但详情受限。

### 加入申请流
- 从家族视图摘要卡发起 `POST /api/spaces/{owner_space}/join-requests` → 空间 owner 收到待处理请求 → 接受后双方成为同空间 active 成员，可见性升级为完整数据。
- 通知载体 v1 从简：站内待处理列表 + 登录后红点提示，不做推送。

## Acceptance Criteria

- [ ] 构造三家庭连通 fixture（A—B—C 相连、D 独立家族）：A 能看到 C 的摘要卡，D 及其家族完全不出现在 A 的任何接口返回中。
- [ ] A 直接请求 C 的档案 API：photo/birth/death/bio/attachments 字段为遮罩结构；name/称谓/世代正常返回。
- [ ] A 通过搜索能命中 C 的名字，打开详情仍是遮罩态；搜索结果中永无 D 家族成员。
- [ ] A 发起加入 B 空间申请 → B 登录看到待处理请求 → 接受后 A 可见 B 的完整档案，家族视图中该空间高亮为"已连接"。
- [ ] 家庭 ⇄ 家族切换动画流畅；折叠某分支后其子树隐藏且布局自动重排。
- [ ] 越权测试套件：以普通用户 JWT 直连 API 尝试读取遮罩字段的原始值，全部失败（集成测试覆盖）。

## Non-goals

- 推送通知/邮件/微信通知。
- 不同家族空间可见性的精细策略（v2）。
- Agent 亲戚推荐（v2）。
- 大图性能深度优化（几十人规模仅做分支折叠即可）。

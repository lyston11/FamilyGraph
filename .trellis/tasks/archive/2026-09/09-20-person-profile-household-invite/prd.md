# 个人公示页邀请入家庭空间，并提供退出空间入口

## Goal

补齐两条缺失的「空间成员自助操作」：一是在 `/people/:userId` 个人公示页，让我把该成员邀请进我选择的某个家庭空间，并明确显示「已在同一家庭空间中」；二是在设置页提供退出家庭空间／家族空间的入口，退出前必须由我本人二次确认。

## Requirements

### R1 个人公示页邀请他人加入我的家庭空间

- 公示页新增「邀请加入家庭空间」入口，仅在我至少有一个 active 成员资格的家庭空间（`kind='household'`）时出现；目标不可见（页面已处于安全不可见状态）时不出现。
- 点击入口弹出空间选择：列出我 active 成员资格的全部家庭空间，逐个显示该目标在该空间的状态：
  - 目标已是 active 成员 → 显示「已在同一家庭空间中」，该项不可选；
  - 目标已有 pending 成员行 → 显示「已发出邀请，等待对方接受」，该项不可选；
  - 其余 → 可选。
- 选择并确认后，走既有邀请命令产生 pending 成员行（`POST /spaces/{space_id}/members`）：受邀人本人接受后才 active，绝不静默拉人入空间。
- 邀请必须是我对**所选家庭空间**的 active 成员资格授权，不是对当前 lineage 上下文的授权；不能因为我在某家族空间是成员就向任意家庭空间发邀请。
- 邀请成功／失败都以服务端状态为准刷新，不做乐观本地副本；失败给出可读文案。
- 本页仍不提供「查看对方家庭」「修改对方资料」「扩大权限」等入口；本次只新增邀请入**我的**家庭空间。

### R2 退出家庭空间／家族空间入口

- 设置页新增「我的空间」分区，列出我全部 active 成员资格的空间（家庭空间与家族空间），显示名称、类型与我的角色。
- 每个空间提供「退出」入口；点击后必须二次确认，确认文案显示空间名与后果（退出后失去该空间的数据访问，需要重新申请才能再加入）。
- 取消确认不产生任何写入；确认后调用退出命令，成功后以服务端状态重载空间列表。
- 授权边界：只能退出**我本人**的成员资格；他人成员资格的移除仍走既有空间治理流程，不经本入口。
- 我作为该空间 `space_admin` 时不得直接退出：必须先在既有流程完成管理员交接，服务端返回的既有错误码原样呈现为可读提示，不做前端绕过。
- 退出当前正在查看的空间后，前端必须切换到仍然有效的空间；没有剩余空间时进入既有空态，不留悬空上下文。
- 退出是既有终态 `removed`：再次加入需重新走申请/邀请流程，本次不新增「撤销退出」。

### R3 回归范围

- 后端：按空间退出命令的成功、非成员、需先交接管理员、不得代他人退出；既有 `DELETE /space-memberships/{member_id}` 行为不变。
- 前端：公示页邀请入口的三种状态与调用参数、无家庭空间时不显示入口、设置页退出二次确认（取消零写入／确认调用）、退出当前空间后的上下文切换。
- 只运行受影响的后端定向测试与必要静态检查，不运行无关的全量高成本验收。

## Acceptance Criteria

- AC1：目标已是某家庭空间 active 成员时，该空间在选择列表中显示「已在同一家庭空间中」且不可选；已有 pending 时显示「已发出邀请」且不可选；其余空间可选并可成功发出 pending 邀请。
- AC2：邀请使用所选家庭空间的空间 ID，而不是当前 lineage 上下文的 ID；我对该空间没有 active 成员资格时服务端拒绝，前端显示可读失败文案。
- AC3：设置页列出我全部 active 空间，退出必须经二次确认；取消不产生写入，确认后服务端状态为 `removed` 且列表已重载。
- AC4：我是该空间 `space_admin` 时退出被服务端拒绝，并提示需先完成管理员交接；前端不绕过。
- AC5：退出当前空间后自动落到仍有效的空间；无剩余空间时进入既有空态，不显示已退出空间的数据。
- AC6：受影响 backend 与 frontend 定向检查通过；未运行的高成本检查如实记录。

# 推荐方案草案：先显示可信骨架，再逐步补齐个人称谓

状态：历史规划草案，保留推导过程，不作为实施合同。2026-09-14 用户已选择“先骨架后称谓”；最终需求、设计和执行顺序以 [prd.md](../prd.md)、[design.md](../design.md)、[implement.md](../implement.md) 为准。代码事实与审查出处见 [current-state.md](current-state.md)。

## 1. 产品体验

推荐首屏先展示当前查看者有权看到、且满足现有路径边界的已确认人物与结构连线。人物名称和结构关系来自已确认数据；需要计算的“与你的称谓”先显示轻量的“整理中”，不把未完成解释成“无关系”。

| 阶段 | 用户看到什么 | 系统完成什么 |
| --- | --- | --- |
| 有有效缓存 | 已完成的个人家谱直接出现 | 验证权限、版本和有效期，命中则复用 |
| 首次计算/输入已变化 | 最新授权骨架，节点可点击/缩放 | 用授权图做有界可达性与骨架准备，无须枚举每对的全部替代路径 |
| 逐批完成 | “已整理 8/29 人”；称谓按批次补齐 | 完整 target 结果通过栅栏、短事务持久化后才计数 |
| 本人结果齐全 | 个人称谓齐全，可继续浏览 | 个人完成不代表全空间作业已结算；其他必需工作继续 |
| 完整发布 | 更新提示结束 | 原子切换完整版本并结算消费水位 |
| 输入变化/失败 | 新骨架或明确的部分完成/重试状态 | 不继续混用旧版本，不无限旋转，不伪造完成 |

首屏“完整骨架”仅指这个查看者的可授权、可达范围；不扩大到全空间人口清单，不暴露隐藏人数。可达性遵循现有最大深度、partner 终止、桥接及 viewer 剪枝规则，不能用无条件 BFS 改变授权或关系语义。

第一轮优先计算当前页面查看者；该查看者内优先当前选中目标及近亲，再扩到远亲。选择只影响调度，不改变关系算法或最后结果。其他已需刷新的账号仍有公平份额；全矩阵预热不占据前台必需工作的关键路径。

## 2. 计算与提交

```text
短事务：租赁作业并固定本次事件上界
    ↓
短读事务：读取一致输入、权限版本、时间边界 → 关闭 Session
    ↓
纯计算：构建一次 viewer 授权图 → 优先目标/有界批次
    ↓
短事务：CAS 复核 → 保存本 generation 已完成结果和批次进度
    ├─ 浏览器可读：同代、当前仍有效的骨架与完整 target 结果
    └─ 后续批次继续；独立 heartbeat/maintenance 照常执行
    ↓
最后短事务：复核必需工作完成 → 切换完整版本指针 + 结算水位
    ↓
发布后的幂等通知/辅助调度；旧代数据另行有界回收
```

“边算边显”发生在受校验的 preview generation；“原子完成”发生在正式发布。每个 target 的主路径、替代路径、称谓、证据作为完整单元提交，不直播递归搜索到一半的路径，也不把不同 generation 的行拼在一起。

generation 建立时记录固定必需工作清单：事件消费与确定性检查、需要刷新的 PFV、必要的卡片/投影变更计划等。未被请求的 DerivedFact 全矩阵仅是可重建缓存预热，不作为所有页面的等待条件。若保留管理员全量预热能力，则作为明确的后台维护工作，不能冒充本人加载进度。

最终事务不能重新逐 pair 解析、构建大型 JSON 或把 staging 全量复制到旧表。投影行预先按 generation 存好，提交只切指针、更新完成状态/水位及幂等副作用登记。findings、卡片等也需定义发布门槛或 outbox：不可在 preview 阶段发通知或调用模型；执行用户动作时仍以当前事实和权限重验。

## 3. 版本、权限与恢复

- 显式区分 `execution_cursor`（本次承诺消费的事件窗口）、`generation_id`（本次计算版本）与 `revision`（同代已提交进度）。预览推进只改变 revision；本人完成不能提前改变 execution cursor。
- 新输入摘要覆盖事实和节点、查看者成员/ref/披露与字段可见性、性别/出生相关数据、桥接、词典/偏好、策略/算法/展示版本。推测层开关/证据/revision 独立分层，不能污染 confirmed 事实或缓存。
- 结构输入、展示输入分开缓存：仅改称谓时复用已验证的结构路径；图或权限改变才失效对应结构结果。自己的 staging、checkpoint、完成事件不能改变输入版本，避免自我触发无限重算。
- 发布快速校验采用与相关业务变更同事务推进的版本记录；审核所有输入生产者，不能只把全局 event 最大 ID 当作输入版本。时间敏感权限另带 `valid_until`，在取数、分批写入和最后发布时复核。
- 每次状态写入用新 Session/数据库 CAS 比较 job、owner、attempt、deadline、generation 与输入版本；续租、失败回队、取消也必须有相同保护。
- 相关输入变化时停收旧批次，将旧代标为 superseded，并同事务保留最高待处理事件水位。合并短时间内重复触发，优先最新输入；不相关事件不重新计算相同图。
- 数据内容变更后，浏览器保留视口和仍获授权节点的位置，清除失效称谓，替换为最新授权骨架。权限收紧后下一次读取即拒绝旧内容和旧 304；不能把“保留旧画面”当作授权例外。
- 进程重启仅在全部输入栅栏一致时复用已落库的完整批次；运行中的半个 pair 重做。重复批次以唯一键去重，不能重复增加进度或创建卡片。

## 4. 性能策略

1. 正确的缓存前置：加载/比较便宜且完整的输入指纹后，命中则不进入路径枚举。允许内部记录确定的 no_path；对外保持不可见/不存在等安全等价，不泄露枚举信息。
2. 图复用：每个 viewer/input 只批量加载和构建一次授权图；同一结构解析产物同时供 DerivedFact 与 PFV 使用。
3. 安全的可达性预检查快速排除断开分量和深度范围外目标；保留现有主路径排序、替代路径与亲缘语义。
4. CPU 工作使用有界独立计算执行器；协调器/maintenance 不能同步等待整族计算，heartbeat 独立。优先采用进程隔离纯计算，避免 Python CPU 长算继续争用 API 的 GIL；这必须与短写事务同时落实。
5. 批次同时受目标数、写入量和调度时片约束。单 pair 也可被取消/让出执行；达到搜索预算表示未完成，绝不改写成 no_path 或已完成。有限重试耗尽后显示明确部分失败并保留可审查原因。
6. 相同输入的周期扫描仍执行到期检查/恢复等轻量职责，跳过图重算。多个空间轮转，前台请求提升优先级但不能饿死其他空间。
7. staging、快照、进程内缓存和过期 generation 具有数量/空间上限；清理与异常恢复同样分批，不能形成新的长写事务。

## 5. 浏览器更新协议

首版推荐复用 HTTP 条件 GET：计算期间约每 1 秒请求一次，短暂错误退避，页面隐藏时暂停并在回到前台时立即重验；本人结果完成后停止高频轮询。无需先引入 WebSocket 或通用实时总线。后续 SSE 可以作为“有新 revision”的提示，实际数据仍经过同一授权读取。

推荐在现有端点增加显式渐进能力参数/协议版本。旧客户端继续收到原 current/安全空态合同；支持渐进的客户端才读取 preview。必要字段：同代标识、单调 revision、骨架版本、目标总数、完成数、明确的未完成/失败状态和建议下次查询间隔。公开字段不暴露其他账号、隐藏目标或内部 worker 身份。

首版返回同一 generation 的累积安全快照即可，先避免引入难以恢复的多层 delta 协议；ETag 需含 generation/revision/权限及最终载荷，返回 304 前照常授权和有效期检查。体积确实成为瓶颈后再加同代 delta/游标。

store 每个 account+space 只保持一条有效更新链，拒收旧 generation、倒退 revision、切空间或登出后的迟到响应。相同骨架只更新节点标签/面板数据，不重排、不 fitView；初次显示或用户主动“适应画布”才调整视口。网络失败不无条件卸载整个画布，但旧数据显示必须受服务端有效期及撤权合同约束，恢复连接先重新授权。

## 6. 验收与实施顺序建议

- 硬验收：SQLite `busy_timeout=5000` 保持不变；冷/热重算及连续至少两次 300 秒调度窗口，登录、lease、maintenance 并发不出现重算长写锁导致的 500。
- 初始性能目标（待实测，不是已达到）：同级部署环境、30 人六代样本骨架首屏 p95 ≤ 1 秒；批次/发布写锁 p99 ≤ 100 ms、单次超过 500 ms 必须查明并整改；同时报告在线请求 p95/p99、第一批称谓时间与完整计算时间，不能只报作业总耗时。
- 规模矩阵：30 人六代真实形态、50/200 人稀疏多代树及单独标注的稠密/断开压力图；旧报告的外推值不当作当前结果。
- 正确性：事实/授权/词典/性别/出生/推测改变；桥接纯时间到期；旧 owner/attempt、迟到失败、重复批次、取消、重启与发布失败；未完成与 no_path 明确区分，事件水位不提前。
- 体验：首屏先可交互、逐批称谓补齐、进度真实、节点不乱跳、选中/拖动/缩放保留、乱序响应不能回退、断网不无限加载。
- 顺序：先补并发复现和完整输入合同 → 抽离纯计算/缓存前置/短事务及恢复 → generation 预览与 API → 前端渐进体验 → 隔离迁移与容量/兼容回归 → 审查发布与回滚。共享模块和迁移串行集成。

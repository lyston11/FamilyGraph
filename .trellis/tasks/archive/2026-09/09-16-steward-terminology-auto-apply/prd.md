# Steward 称谓自主优化与自动应用

## Goal

管家根据当前空间中每位查看者获准的关系路径，自主维护他对其他人的准确、自然称谓。当前用户进入家族树、人物档案或查看通知中的关系表达时，直接看到改善后的叫法，无需先逐条确认通知或建议。

用户已授权本任务的设计修改、确定性修复、模型增强启用与服务器部署；实现仍按规划评审、隔离 worktree、检查、部署和归档顺序进行。后端与 Agent 服务继续运行于服务器。

## Background

沿用 09-13 称谓闭环与自动称谓任务的既有架构，不另建 Agent runtime 或称谓审批系统。原设计已经规定自动应用、个人/空间词条优先及可撤销；本任务补齐实际效果、内容正确性和部署启用。

当前源码核查（main@621284d）：

- `backend/app/services/relationship_resolver.py:394` 输出原始路径码；`backend/app/services/terms.py:1100` 精确查词，没有为父母展开的旁系路径查等价内置词。例如 `Um-Dm-Dm` 显示“兄弟的儿子”，已有 `Bm-Dm` 词条为“侄子”。
- `backend/app/models/term_registry.py:134` 的四条配偶旁系内置词与 `Sm=丈夫/Sf=妻子` 定义相反，扩大匹配前必须修复。不得继续引用先前方向颠倒的示例。
- `backend/app/services/steward_terminology.py:782` 会把 derived baseline 本身生成 `shorter_chain` 建议。原设计曾允许这种可选保留（归档 design §2），本任务明确收紧为无实际改善不生成建议。
- `frontend/src/views/NotificationsView.vue:78` 将这类可选称谓纳入“待核实”列表，与用户本次明确要求冲突，需改为非待办呈现。
- 模型辅助和自动投影链已存在；先前生产观察显示 terminology 未启用。本任务实施时重查有效配置，不把历史 535 条等计数当作实时状态或改善率承诺。

## Requirements

### R1 自动显示与查看者隔离

确定性规则可证明的自然称谓自动用于基础显示；合格模型改善自动应用到当前账号、空间和目标的个人投影。两种方式均不依赖任何建议提交或通知操作。个人家族树、档案与通知中的个人关系表达同源；第三人之间的结构边仍按真实端点表达。无权限的中间人物、未公开生日及其他用户的私人偏好不得进入计算或模型输入。

### R2 准确命名优先于缩短文字

补齐共同生物父母路径与旁系词条的安全等价查找，保留原路径和事实身份；涵盖侄子/侄女、外甥/外甥女、叔伯/姑姑/舅舅/姨妈、堂表亲等现有内置词能够证明的关系。未知性别或长幼用中性词，不猜哥哥/弟弟、伯父/叔父。继亲、收养、监护、伴侣、跨空间桥不得被误转为血亲或配偶。

修正四条配偶旁系内置词及存量内置行。盘点实际可见的剩余常见长链，补有明确语义依据的标准词/组合；无法唯一命名的关系保留可解释短链，不强求所有路径都有单个专名，不把任意模型造词作为正确性来源。

### R3 保留用户选择与反馈

本人显式词条及已生效空间词条优先，自动优化不能静默修改它们或伪造 TermUsage、SourceFact。用户可主动固定叫法、改口或恢复默认；恢复只作用于本人目标，阻止同语义同词反复应用，旧建议不能撤销新版投影。基础显示改善不为满足统计而写相同值的冗余 override。

### R4 消除自我推荐和称谓待办

没有更好叫法时不生成与 baseline 相同的建议。合格自动投影的可选固定/恢复入口留在人物称谓区，文案明确“已自动优化”；它不是审批入口。新旧 `term_preference` 均不进入“待处理/待核实”及相应待办计数；历史通知可按原权限查看，仍不要求处理。真正的关系确认、成员加入及授权待办保持原语义。

存量纯 baseline 建议退出活跃消费和操作范围，保留历史及用户已固定/恢复记录，不批量删除或伪造已采纳状态。不新增 TTL。

### R5 模型增强实际启用

沿用既有 Steward Provider、协议、预算、云许可和 batch/attempt 调度，启用本次部署的 terminology 环境、平台及适用空间开关；其他 assist 类型不随之开启。先在隔离环境证明完整调用链，再在服务器验证真实模型调用、合法写回和消费者显示。

模型只处理当前 viewer 的有界、获准输入。输出由服务端按路径和合法词义核验，错误或无改善结果直接放弃，无需推给用户审批。已有有效结果不能因重复 core、空输出或网络失败被无故清除；同输入不反复调用，unknown 不重发，不增加原调用预算。不擅改现有 Provider 或绕过 cloud_allowed/local_required。

### R6 刷新、存量兼容与部署

词表、显示规则、相关事实、授权和偏好变化后，实时解析、模型候选、哈希与已发布 PFV 一致刷新；不能仅改新建数据库，也不能部署后继续显示旧缓存。存量升级先在线备份、隔离演练，再通过正式迁移/领域刷新执行。验收脚本显式设隔离 DATA_DIR 并断言实际数据库路径，禁止在生产写测试人物、消息或关系。

## Out of scope

不新增关系事实审批替代机制、不读取私人聊天/RAG、不开展跨空间发现；不无限扩充方言词库，不承诺所有深层关系都有唯一专名。09-11 的共享知识、新地区包及个人路径解释研究继续独立。不重建 Provider 治理、Steward 调度或树布局。

## Decisions

本任务是同一称谓生成与消费闭环，Terms/Steward/建议有效态和前端共享输入，按一个任务串行交付，避免拆成可被单独部署但语义不一致的子任务。已明确的产品选择无需再次征询；剩余步骤为完整规划评审及实施。

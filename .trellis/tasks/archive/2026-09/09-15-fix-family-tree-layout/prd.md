# 修复前端家族树层级布局

## 目标与用户价值

修复 `/family-tree` 树状模式的空间布局，使节点按照真实的父子层级形成可读的分支结构：每一代在正确的纵向层级，兄弟姐妹及配偶保持同代但不挤压，子树尽量围绕其父母展开。用户应能直接看出家族分支，而不是看到每一行节点像独立紧缩的横向列表。

## 已确认事实

- 画布由 `frontend/src/composables/useFamilyTreeCanvas.ts` 构造，布局入口为 `applyTreeViewLayout`。
- `frontend/src/composables/familyTreeLayout.ts` 当前先按连通分量和 rank 分行，再对每一行独立 `placeRow`；各行从 `x=0` 重新开始，仅用有限次重心排序，不计算父母子树的整体宽度与中心锚点。
- 页面随后在 `FamilyTreeView.vue` 中执行 `fitView`，几十个节点的总宽度会进一步压缩屏幕视觉比例。
- 节点卡片固定宽度 192px、默认列距 280px、行距 240px；现有单元测试覆盖世代约束、同代不重叠、确定性和冲突回退。
- 结构边只来自 confirmed `topology_edges`；推测节点不应改变 confirmed 节点的世代约束。

## 范围内需求

1. 保留现有 parent / spouse / partner / sibling 的世代语义和冲突返回 `null` 的安全行为。
2. 改造树状布局的横向分配，使同一父母组的后代作为连续子树占据空间，父母/配偶块位于其后代子树的中心附近，而不是每行独立从同一 x 起点排布。
3. 保证每张卡片在同一世代不重叠，并保持配偶/伴侣块内部的固定相邻间距。
4. 保持布局确定性：同样的节点和边无论输入顺序如何，输出位置一致；所有节点都必须获得位置。
5. 保持现有布局失败回退自由画布的行为，并补充能复现截图问题的布局回归测试。
6. 不破坏现有拖动位置、树状/自由画布切换、连线端口和推测节点单独摆位逻辑。

## 范围外

- 不改变后端投影、权限、关系事实或 API 合同。
- 不把个人摘要边或推测边加入 confirmed 树结构。
- 不重做 MemberNode 视觉样式、导航壳或画布工具栏。
- 不引入新的布局依赖；优先在现有纯函数中修复。

## 验收标准

- 给定至少两代、多个父母组和多个子女组的结构数据，输出中每个父母组的后代子树横向连续且与其他分支有明确间隔，不再表现为各行从相同 x 轴紧缩排列。
- 同代任意两张 192px 卡片的水平间隔不小于卡片宽度；配偶/伴侣块仍以 `COL_SPACING` 相邻。
- 现有 13 个 `familyTreeLayout` 测试和新增回归测试全部通过。
- `frontend` 的 `npm run lint`、`npm run type-check`、`npm test`、`npm run build` 通过。
- 页面仍能在树状布局冲突时切换自由画布并显示原有提示。

## 完成状态

用户已批准实施。算法、页面坐标消费、回归测试和前端质量门禁已完成，具体证据见 implement.md。树模式拓扑变化时重新布局；同一拓扑的称谓更新、空窗恢复及自由画布拖动位置继续保持稳定。

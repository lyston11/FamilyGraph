# PRD：Agent 记忆与知识能力扩展准入

## Goal

把审计中所有尚未接通、需要产品选择或需要收益证据的能力变成可评估的方案，给出采用、保留现状或延期的条件，避免把配置/状态累积误称为 Agent 已经会学习。

父任务：[治理总任务](../09-13-agent-memory-rag-remediation/prd.md)。规划后用户已回复“执行”，E 进入研究与评估，优先完成隔离的 MR-23/MR-26 复现，不默认实施下表功能。真实模型质量/成本实验另行决定。所有新增记忆/检索能力复用 A/B/D 的来源、权限和索引合同。

## Current facts

Assistant 每 Run 一次检索，没有 search_memory/search_rag/remember 工具；默认 extractor 返回空，聊天无保存动作；授权导入只有 service；embedding_status 只是占位。Pi 有自动压缩，但无跨 Run 持久摘要。

Steward 持久化的是进度、结构候选、去重与部分冷却，模型输入没有历史反馈；shared RAG、correction_preference/term_usage 投影未进入生产消费链。真实个人称谓由 TermRegistry 持久化并使用，不能说项目完全没有称谓记忆。线上模型辅助曾在既有任务中有成功记录，本轮没有验证当前线上状态。

## Requirements

- E-R1：每个议题都记录用户收益、输入输出、来源及可见范围、成本、失败/回退路径、依赖、可运行评估和采用门槛；延期有明确原因和下一触发条件。
- E-R2：只读设计可以与 A～D 并行；性能/质量比较必须在 A～D 的稳定基线上进行，不把现有已知坏检索当作夸大新方案收益的基线。
- E-R3：新工具、自动提取、外部模型外发、持久摘要、物理清理等改变产品行为的方案，在选用前补齐对应设计与范围；本任务不默认开启。
- E-R4：完整复现 MR-23 的模型候选→数据库→后续 core→Suggestion 路径，以及 MR-26 的混合键族重建风险；直接 upsert 单测不足以闭环。
- E-R5：把 Suggestion 冷却限制、ActionCard 已有生产读写且行为投影开关开启时生效的冷却、异步下一 core 投影分开；不推断今天线上生效。在未决定重现语义前保留同证据驳回，不主动新增提醒。
- E-R6：沿用既有任务所有权。shared RAG 归 followups；已完成平台开关作为基线。新授权称谓闭环由 [专属总任务](../09-13-steward-kinship-capability-closure/prd.md) 负责生产与第四类开关扩展，E 不重复实现或改写其状态；MR-23/26 修复仍归既定 P2 包。
- E-R7：研究只用合成/已授权数据；记录脱敏结果、版本与命令，不把家庭正文、密钥或完整模型 prompt 贴入 task。

## Acceptance Criteria

| ID | 可观察结果 |
|---|---|
| E-AC1 | E-O1～12 及 MR-15 均有设计、评估协议、采用/延期门槛和唯一后续所有者；没有把预留字段当成可用能力 |
| E-AC2 | 检索/主动工具/语义候选在相同冻结集下比较，报告 Recall@5/MRR、引用有效率、延迟分位数、调用量/成本和隐私反例；无收益可明确延期 |
| E-AC3 | 自动/显式保存、导入、摘要和编辑设计通过来源撤销、错 scope、legacy、派生消息和敏感资料反例；候选不被自动确认 |
| E-AC4 | 全请求预算方案覆盖至少两类上下文窗口、长中文/工具结果/新 user 超长、压缩后复核与清楚失败；不靠静默丢历史通过 |
| E-AC5 | MR-23 多 job 重现/反证与最小修复建议完整；MR-26 混合键族回放保留测试明确；两者未执行时保持“待验证”而非已修复 |
| E-AC6 | 排序/反馈输入及消费者有实际出处；TermRegistry 不被重复取代；Suggestion 到期与异步投影语义有选择记录或明确延期 |
| E-AC7 | 给既有 Steward 能力任务的共享检索/失效/引用交接可引用；与平台开关任务无文件/迁移重复所有权 |
| E-AC8 | 每项结论注明证据等级、SDK/代码版本和限制；实际测量未执行就写未执行，线上状态与模型质量不冒充已验证 |

## Dependencies and completion boundary

本 PRD/design/implement 是本轮已授权的规划交付。E 实际执行后才回填结果和采用/延期决定；能力未被选用时不算实现缺陷，也不能标为“已接入”。

后续授权例外：用户已选用称谓能力闭环；这不改写 E 的既有实验结果，也不意味着称谓代码已实现。E 保留一般反馈排序、shared RAG 交接和真实质量评估；称谓生产、viewer 上下文、个人优化投影与反馈消费者归上述专属任务，不继续作为“未被选用”延期。

来源/检索/索引评估以 A/B/D 为前置，摘要/预算以 C 修复为前置。MR-23/MR-26 的纯合成复现可独立推进。待采用的业务补丁需明确实施任务和 worktree，E 的只读研究职责不直接改生产代码。

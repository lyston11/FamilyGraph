# 空间加入需房主审批 + 成员间自由关系词标注

## Goal

把「进入一个空间」都收到房主手里，并且加入时必须说清「我和对方是什么关系」：家族邀请码兑换与邀请都改为房主审批链；加入时填写的自由关系词作为两人之间的一条标注边，显示在家族树与个人页上，且不参与亲属路径推导。

## Requirements

### R1 审批链（房主 = 该空间 active `space_admin`）

- 邀请（公示页 / 空间治理面板）：发起人邀请 → **房主批准** → 受邀人接受 → active。
- 申请加入（公示页 `join-by-user`）：申请人申请 → **房主批准** → active（申请人提交即为其同意）。
- 邀请码兑换：兑换 → **房主批准** → active（兑换人提交即为其同意）。
- 申请人/受邀人/兑换人都不得自批；房主自己受 `SPACE_MANAGER_TRANSFER_REQUIRED` 约束（既有语义不变）。
- 房主批准与受邀人接受是两步：房主先批准，受邀人再接受；顺序颠倒时受邀人接受应被拒绝（提示等待房主批准）。

### R2 加入必须填写与对方的关系词

- 邀请、申请、邀请码兑换三条路径都必须提供关系词；缺失 → 422。
- 关系词是**自由文本**，不做词表约束（兄弟、朋友、闺蜜等均可），长度上限 64。
- 关系词描述的是**发起方与对方两人之间**的关系；由发起方在提交时填写。

### R3 关系词标注边的展示与修改

- 关系词以一条**标注边**显示在家族树上该两个节点之间，并在个人页显示。
- **双方都可以改**：该成员本人与其关系对端（发起方）都能修改关系词，改完即时生效，无需对方确认、无需房主审批。
- 改词只影响显示，**不产生、不修改任何亲属事实**。
- 空词/清空 = 移除该标注边。

### R4 关系词绝不参与亲属推导（安全底线）

- 关系词边**不进入** `relationship_graph` 的路径推导、可达性、世代计算或拓扑边；填「朋友/闺蜜」不得让两人产生任何亲属联系或扩大任何可见范围。
- 关系词边只在读取时按「两端都在本次授权节点集合内」渲染；任一端不再是该空间 active 成员或不再可见时，该边不返回。
- 家族树的亲属连线仍只来自 confirmed 亲属事实，与本次改动无关。

### R5 退出即时清权（现状确认，不改语义）

- 退出只需本人二次确认，无任何审批。
- 退出后立即失去该空间可见性（读取按 active membership 现算）且相关投影失效；关系词标注边随之不再渲染。

### R6 回归范围

- 后端：三条路径的审批链与顺序、自批拒绝、关系词必填与长度、双方可改与第三方不可改、标注边不进入亲属图。
- 前端：三条入口的关系词输入、家族树标注边渲染、个人页显示、修改入口。
- 只运行受影响的后端定向测试与必要静态检查。

## Acceptance Criteria

- AC1：邀请需房主先批准、受邀人后接受，两步都完成后才 active；缺任一步不 active，且申请人/受邀人不得自批。
- AC2：申请加入与邀请码兑换都需房主批准后才 active；兑换人/申请人不得自批。
- AC3：三条路径缺少关系词时 422，不落 pending 行。
- AC4：关系词以标注边出现在家族树两端点之间，并在个人页显示；该成员本人与关系对端都能修改，第三方不能。
- AC5：关系词不影响亲属路径：填「朋友」后两人之间不产生任何亲属边，也不扩大可见范围或家族树可达性。
- AC6：任一端退出后，标注边立即不再返回。
- AC7：受影响 backend 与 frontend 定向检查通过；未运行的高成本检查如实记录。

# A：助手响应延迟分段定位与验证

## 1. 状态与依赖

父任务：`09-17-dual-agent-latency-result-integrity`；对应父 R1/R4/R5/R6/R7、AC-01/06～09。状态 planning，本轮只写规划，不写业务代码、不发模型请求、不变更配置、不使用子智能体。

实施依赖：先冻结父任务共同基线；本任务的基线测量可先于 B，但任何共享后端代码改动必须串行，默认 B 完成后再推进本任务实质修复。不得把父子关系当隐式调度规则。

## 2. 用户问题与事实

用户感觉助手回应持续很慢，需要明确等待位置并消除可避免的等待。不能把“后端是 streaming”视为“用户已经能及时看到正文”。

已确认：

- 请求经 sidecar 和后端 ProviderGateway，实际模型流由后端出口转发；模型配置、预算与权限在服务端裁决。
- sidecar 单实例执行一个 run，租赁/续租、context/RAG/session 构造、SDK 压缩/重试、工具执行、事件持久化均可能占用时间。
- 当前 `mapSessionEvent` 忽略 message_update/delta，只在 message_end 转出非空 assistant 正文。首次正文可见时间因此不同于上游第一块正文。
- 现有前端已有 queued/慢生成反馈；09-15 已做空工具消息过滤等修复，09-16 空最终回答失败合同已落地，不能重复或退回。
- 09-15 单次约 33 秒生成只证明历史个例；当前生产阶段分布未知。既有 admin latency 对助手只有 run 总体时间，不提供准确 lease/首字。

## 3. 目标

1. 一份能复核的耗时拆解，覆盖用户点击到首次正文、最终回复与失败。
2. 对程序性排队/传输/展示额外等待，只有证据成立才选择最小修复。
3. 若主要瓶颈在上游，给可测量的选择及质量/成本差异，明确哪些还未解决，不伪造“优化完成”。
4. 过程中保留工具权限、引用、错误处理、取消和完整历史/默认自动压缩。

## 4. 需求

### A-R1 阶段证据

至少能区分提交/入队、等待 worker、context/session 准备、Provider 每轮请求/首正文/完成、工具阶段、事件持久化/SSE/渲染、最终结算。多轮模型和工具调用须逐轮关联；首控制事件、心跳、工具事件、reasoning 都不冒充正文首字。

利用已有安全元数据，缺失时只增最小必要观测。历史无法观测的值标 unknown/null；不得以可续租的 lease_expires_at 减固定 TTL 伪造首次 lease。

### A-R2 归因与比较

分别解释“首字很慢”“首段显示晚”“工具后长等待”“排队未开始”“最终完成慢”。每项结论至少有同一 run/attempt 可关联证据或受控复现，不凭总耗时或模型名字判断。

同配置比较必须列 Provider/协议/模型/推理设置来源、输入规模、工具轮次、压缩与重试、缓存是否真实可观测、样本窗口及失败分母。样本少则展示个体时长/范围，不宣称稳定 p95。

### A-R3 最小改进与停止条件

若发现程序性额外等待，修复共同且正确的边界，留下针对时序的回归与前后量化结果；不通过假进度或立即输出模板文字制造模型更快的印象。

若仅为完整消息后才显示的体验问题，先交付增量展示设计选择；未批准前不增加公开 delta 事件。若主要是上游慢，给出选择而不擅自换模型/降推理档位/扩大输出预算。没有实测收益时“延迟诊断已完成”和“慢响应已解决”必须分开，父验收仍保留未解决项。

### A-R4 质量与运行时不退化

- Provider 仅经既有网关，云许可、token cap、run execution fence 和工具授权保持。
- 保留 SDK 默认自动压缩及从 SessionManager 恢复的允许历史；不改为 recent-N 或独立摘要。
- 空工具 turn 不产生空气泡，空最终回答不能成功；有正文 length 与取消/失租按既有合同。
- `succeeded` 不能由部分文本/工具前说明充当最终回答。
- 卡片/citations/webCitations 只由现有结构化合同绑定；诊断不展示 chain-of-thought。

### A-R5 反馈与错误

现有 queued/生成/工具反馈应与真实状态一致，错误/超时/取消都终止等待且原因可解释。若确有提示器时序 bug，可在既有状态模型中修复，不添加伪进度百分比。

本任务不承诺逐 token 渲染；若采用该方案，重连/重复 delta/消息 ID/终态替换/部分失败必须另行冻结合同后执行。

### A-R6 安全观测与部署

不写正文/prompt/thinking/工具返回/密钥；只记录关联 ID、阶段、时间/时长、长度/轮次与安全错误码。新增字段校验由实际 schema 真源定义，backend/sidecar/front-end 不能各造同名不同义字段。

真实模型测试先合成少样本、上限明确、沿已授权 Provider；不重发用户私密历史作压测，不把本地代理可达当模型性能证据。生产配置本任务默认只读，调参须显式选择。

## 5. 验收

| AC | 通过标准 |
|---|---|
| A-01 | 基线能准确标出可测与缺失阶段；至少覆盖无工具短答、一次只读工具、已有长历史/压缩受控场景、排队和失败/取消 |
| A-02 | 同 run 多轮 Provider/工具/重试不误算为单次模型推理；首控制事件/工具 turn 不计正文首字 |
| A-03 | 本地延迟注入明确区分上游流首正文与最终 message_end、公共事件与浏览器可见；测量本身不发额外模型请求 |
| A-04 | 已证实程序问题有最小修复回归与同配置受控前后差异；若未证实则报告证据和选择，不能勾“已提速” |
| A-05 | worker 租赁、取消/失租、Provider 错误/重试、空最终回答、历史与压缩、工具/引用绑定全保持 |
| A-06 | 前端工具/生成反馈不提前结束、不永挂；失败原因可见，SSE 重连无重复消息；未引入跨账号残留 |
| A-07 | 安全字段与脱敏哨兵通过，旧数据/旧客户端兼容；受影响包及 API smoke/浏览器真实链路满足 |
| A-08 | 真实小样本按授权上限完成，报告全部成功/失败与无法观测项；最终结论区分测量、程序优化、展示收益和上游残余慢响应 |

## 6. 非目标与决策门

不扩大 RAG/记忆、不重构 SDK、不新建监控平台、不默认多 worker 并发、不强制预热/缓存、不修改已锁定模型来源。以下选项先提供证据和设计再让用户选：逐字显示；更快模型/推理档位；新的手动重试 UX；并发/预算扩容。

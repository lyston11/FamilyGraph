## 2. 分离两条链路

```text
助手：浏览器提交 → API 入队 → sidecar lease/心跳
      → context/SDK session → ProviderGateway → 上游流
      → SDK 的完整消息/工具轮次 → 事件保存 → SSE → 浏览器

管家：领域触发/定时扫描 → core job → 确定性 PFV 发布
      → detached delivery → assist batch lease → 串行模型调用
      → 调用审计/合法产物 → 写回栅栏 → 投影 → 读取消费
```

助手有独立 heartbeat 续租；不能用管家固定批次租约解释助手慢。管家模型 HTTP 不得进入 core 写事务。两个链路可能共享上游或 SQLite 资源，但必须用观测证明竞争，不凭同一模型名推断。

## 3. 观测设计与时间语义

| 阶段 | 首选证据 | 不可替代它的字段 |
|---|---|---|
| 助手排队 | run 入队时间 + 首次成功 lease 的权威时点 | 会随 heartbeat 变化的 lease_expires_at |
| context/SDK 准备 | 相同 attempt 的前后 monotonic duration | 消息数本身 |
| Provider | 请求发起、首响应字节、首正文、结束、请求次数 | /models 返回 401、首心跳 |
| 工具 | 同 run/turn/tool_call_id 的开始/结束 | 工具正文或 reasoning 输出 |
| 显示等待 | message_end/事件提交/SSE 收到/渲染的对应关系 | 将公共 SSE 存在视为逐字流式 |
| 管家等待 | 注册/lease/发送/保存/应用的分段时间 | generation 总行数、core 成功 |

区分首响应字节、首正文 token、首完整消息、最终回答。上游 SSE 控制事件或 reasoning 均不算用户首字。一个 run 可有多个模型/工具轮次和压缩请求，分别编号；并行或交叠阶段不做错误的加法。

本地 duration 用 monotonic；跨进程以 UTC 关联并记录时钟偏差/精度。不把浏览器 monotonic 与服务端 UTC 直接相减。原来没有的时间戳保持 null/unknown。成功、超时、失租、取消、unknown 均计入总体状态分母；时长分位数明确样本选择与删失。

实现时优先复用现有事件/审计，在确认盲区后选择最小扩展。若新增落库字段，采用 nullable 的向后兼容迁移；不提前为未证实需求造完整 trace 平台。任何 internal 字段新增都先以服务端 schema 定义并两侧联调。

## 4. 管家可靠性方案

目标方案：每笔调用在有效租约下完成后，先独立保存安全审计与已验证产物，再进行下一笔网络请求；不再把所有成果只留在内存直到批次尾部。业务应用仍独立复核权限、输入版本、Provider 与租约。

这会改变当前“一批统一审计”的实现节奏，但不解除 owner/attempt/deadline 的执行身份栅栏。对“第一笔返回后就失租”的结果仍不授权旧执行者强写；通过可中断总截止与收尾预留减少此窗口，无法确认者仍如实 unknown。

混合批次必须单独设计：当前恢复器的 `has_unknown` 优先于 `applied_products`。改成逐调用持久化后，还需让独立成功产物在 recovery 身份下通过原有栅栏应用，不因别的 attempt unknown 而全部失效。保留失败/部分失败的真实状态，不能把“一个成功”当作“整批全成功”。优先复用现有 attempt 状态，不预先新增批次状态枚举。

总时限须从单次请求发起即固定，覆盖连接、发送、headers、读取和解析；单次截止不晚于批次可用时间减去收尾预算。慢速分块不能每块重置总时限；超时应关闭底层请求，不能用新线程超时返回却任由原调用占用资源。具体采用现有 HTTPX/asyncio 或同步可取消方案，先以 transport 复现及依赖版本核查确定最小实现，不在规划期猜写调用方式。

详细状态矩阵在 B 子任务设计。

## 5. 助手方案边界

助手先测量，后选择最窄改动。当前确定“公共流只传完整 message_end”，不能确定这占用户等待的大多数。已有排队/慢生成提示与空消息过滤不应重复实现。

- 若排队主导：核对 sidecar 健康、租赁授权、单实例占用和重试；不默认提升并发。
- 若上游首正文慢：核对实际请求配置、代理与 SDK 重试，不伪造缓存命中或擅自改推理档位。
- 若正文已在 SDK 产生但页面长时间没收到：报告展示延迟；增量显示的事件 schema、重放/去重、权限、部分答案失败处理、最终引用绑定的完整合同由 `09-18-assistant-low-latency` 承接（原 H 已归档；**该任务已完成并归档，真实浏览器验收通过**）。
- 若工具/context/压缩主导：使用匹配阶段的证据；保留 SDK 自动压缩和完整历史合同，不引入第二套摘要或固定最近 N 条截断。

## 6. 测量策略

受控实验用合成文本和 fake transport/本地 HTTP 服务证明时序；慢 chunk、多个串行调用、短租约等场景用可控时间优先，不用分钟级 sleep。

后续真实测试先只读现有安全元数据；少量真实合成调用前明确样本、次数/token 上限、隔离 DATA_DIR、计费及获授权 Provider。小样本列全体值/范围，不包装稳定 p95；若可用样本足够，再按固定窗口报告分布。真实 baseline 与 after 必须标注同配置与网络条件，不能将历史 30s timeout 数据同当前 60s 的成功样本直接比较。

## 7. 兼容性与安全

- 既有 runtime、模型选择、云许可、预算和 schema 校验保持；unknown 不自动重发。
- 不把历史 unknown 改为 succeeded，不批量清理幂等键或修改语义 hash。
- 引入新审计字段时旧行为空，不回填虚构阶段时间；新旧客户端保持兼容，字段 extra-forbid 时明确升级顺序。
- 新日志不得包含 prompt/正文/thinking/工具结果或真实凭据；使用合成敏感哨兵验证。
- 模型结果不是亲属事实，baseline 始终可用，称谓不变回待办。

## 8. 风险与备选

| 选择 | 风险/收益 | 本轮决定 |
|---|---|---|
| 只增大超时/租约 | 允许等更久，不能减少模型时间，也不根治尾部统一审计 | 不作为修复 |
| 逐调用保存 + 混合恢复 | 缩小结果丢失窗口；增加短事务，需验证写锁与所有 kind | 首选设计 |
| 串行改并发 | 可能提高吞吐，也可能限流、预算争用及数据库争用 | 暂不选 |
| unknown 有限重试 | 可能恢复能力，也可能重复计费/重复请求；上游幂等未证实 | 不改变当前规则 |
| 增量正文显示 | 可降低可见等待，不改变上游推理；跨层公开协议改动 | 诊断后另行评审 |
| 更轻模型/档位 | 可能提速，存在质量与治理合同变化 | 诊断后提供选择 |

## 9. 发布与回退

执行批准后先在子任务 worktree 逐步验证，共享模块串行。先 B 后 A 的实质修复；A 基线可先收集。上线需匹配实际拓扑、迁移及服务进程；本地 Vite HMR 不等同远端 sidecar/backend 已更新。

回退以已批准的代码/单个配置键为单位，不覆盖整份 env、不回滚业务事实、不破坏性降级数据。新旧审计/产物兼容性必须先演练；未知结果保守规则在回退后仍成立。已有成功成果不得因回退被批量删除。

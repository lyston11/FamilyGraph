# Steward 称谓能力闭环与推荐语义统一

## Goal

让管家按每个用户的视角自动维护可读、准确的亲属称谓，并使通知、档案和家族树使用同一结果。用户不必逐条批准称谓计算或优化；模型能在已有关系依据内改善称呼，用户主动设置的叫法始终优先。

用户于 2026-09-13 明确要求补齐四项能力、解决通知中的“生物学亲子”、创建并执行总任务，同时修改冲突的未执行规划。当前交付为可评审的实施包，尚未运行 task.py start。

## Requirements

### R-01 管家统一生成个人化表达（P1，A）

通知列表、建议详情、个人关系详情及推测面板均使用服务端同源称谓。服务端使用可信的 account/space/viewer 上下文，保留“谁是谁的什么人”的方向。前端不得从事实枚举、名字、性别或路径另算称谓。推测使用“可能是”等明确状态，不能因称谓自然就宣称关系已确认。

默认界面不再显示“生物学亲子”等存储分类。父亲/母亲/子女来自现有称谓能力，未知性别和长幼使用中性称呼；收养、继亲、监护、配偶和伴侣不互相改义。结构连线仍描述两个真实端点，不能套用 viewer→target 摘要。

依据：F02/P1，`steward_suggestions.py:575–599`、`SuggestionReviewDialog.vue:36–59`；F11/P1，前者直接取 User.name，也需改为当前可见显示值。

### R-02 打通已有结果的 API 与刷新合同（P1，A/B）

修复 derived 来源在 API schema/前端类型中缺失造成的错误，统一来源枚举。通知和普通 GET 不调用模型、不创建称谓或事实。授权、事实、个人/空间词条或模型投影失效时，不继续展示失效旧结果；复用现有后台刷新和安全降级。

依据：F03/P1，`terms.py:993` 返回 derived，`schemas/kinship.py:32,62,75,96` 不接受；隔离校验已复现 literal_error。

### R-03 自动生产并应用称谓优化（P1，B）

Steward 作业发现可优化称谓，生成绑定本人/目标/相关依据的 term_preference 建议。来源包括确定性长链简化、本人已明确表达的用词证据及通过校验的模型产物。纯显示改善自动生效，不调用关系提案、关系确认或授权申请。

日常计算和自动建议不逐条创建待办通知；在现有档案称谓区提供“管家建议”“保留为我的叫法”“恢复原叫法/改口”等可选操作。现存称谓通知按无需处理展示。无实质改善、重复作业、模型无合格输出均不制造新建议。

依据：F04/P1，`steward_suggestions.py:176` 固定 viewer_account_id=None，`:270` 没有称谓生产分支，`:758` 已有本人提交处理。

### R-04 模型在关系依据内优化称谓（P1，B）

新增专用 terminology prompt/schema，允许模型返回自然称谓或更简洁的组合叫法。输入限当前查看者获准路径、已有叫法、可公开的相对长幼和本人相关反馈；不读取私人会话、其他用户偏好或跨空间资料。服务端核验输出含义，不把模型自报概念码或置信度视为证明。

模型不得改关系端点、事实类型、确认状态或可见范围。无法校验、语义冲突、无依据长幼判断等输出自动放弃，保留当前仍有效的称谓；无有效自动结果时使用确定性基线。candidate 仍只产原子关系线索；新称谓能力通过独立 kind 接入。

依据：F05/P1，`steward_assist.py:63,104–124`；F06/P1，`:321` 的 candidate 输入是 space-wide，不适合个人称谓。

### R-05 保护偏好与可撤销反馈（P1，B）

个人及已生效空间词条优先于自动优化。模型产物只存为可重建的个人显示投影，不静默写成显式偏好、不伪造 TermUsage、不计入两人共用空间别名的晋升门槛。主动保留复用 set_personal_term，并说明个人词条按本人概念跨空间生效。

恢复原叫法即时回退并抑制同语义、同建议再次应用；关闭面板/已读不等于拒绝偏好。相关事实或规则变化时重验，单纯无关事实变化、prompt 版本变化或时间到期不重新骚扰。反馈只作用于本人和对应称谓，不能清空其他推荐冷却键。

### R-06 通知语义与操作状态一致（P1，A）

列表、详情、待办计数和允许动作使用同一当前用户有效状态，含本人忽略、终态、过期、授权和证据失效。旧通知可按 ID 获取详情，不依赖首页 20 条缓存。提交后保留关联提案和真实状态，不宣称双方都必须确认。

只有模型候选和整空间快照时，不显示“已有 N 条事实证明”或“确定性推断”；有可验证相关路径才显示依据，否则明确待核实。已由确认路径得到的称谓，不再生成让用户确认称谓的关系提案。同一来源的通知与推测树使用一致的显示和处理状态。

依据：F07/P1，`steward_suggestions.py:286–329`；F08/P2，`notifications.py:190`、`allowed_actions:487`、`NotificationsView.vue:125`；F09/P2，`stewardSuggestions.ts:99` 丢弃提交结果；`InferredEdgePanel.vue:158` 夸大依据。

### R-07 复用执行与治理机制（P1，B）

terminology 接入既有 batch/attempt、预算、Provider、平台/空间开关、出站约束、恢复和统计。一次调用只绑定一个 viewer，发送前和写回前重验同一输入版本。模型关闭、不可用或超预算时确定性称谓继续可用；不得用 GET 或第二套 runtime 绕过治理。

新开关默认关闭，沿用现有辅助能力策略，提供可达配置入口与有效状态。fake transport 必须证明开启后的真实生产调用。交付分清“代码已接通”“本环境已开启”“真实模型质量已验证”。

### R-08 修订路线图冲突（P1，总任务）

更新仍把本期称谓能力整体延期、仅研究或禁止模型称谓的有效规划，将生产所有权归本任务。保留其他任务状态、结果和独立职责；远端已完成的推测层、平台治理不重新开启。共享文件和 migration 串行交接，见 [任务对齐](research/task-alignment.md)。

## Out of scope

- 家族树几何归 topology；不把结构线改成以本人为中心的称谓线。
- 不自动确认新关系、认领、邀请/加入空间或扩大权限；不重设计真实关系同意规则。
- 不新增私人会话读取、shared RAG、跨空间发现、开放工具或地区词库覆盖承诺。
- MR-23/26 研究已由记忆 E 交付，一般候选证据版本/键族业务修复归新建 steward-memory-evidence-projections；称谓链不依赖这些尚未实施机制。
- 真实关系提案最终确认的成环/证据留存等独立问题记入审计，本期不扩展确认入口，也不宣称这些问题已修复。
- 不默认调整线上开关、运行真实家庭数据模型实验或部署；以隔离数据库和合成数据完成生产接线验证。

## Decisions

称谓改善是管家的自动显示职责，偏好选择是用户可选操作；个人/空间词条继续优先。没有尚待补充的业务事实，最后的阶段评审覆盖本文件全部范围和验收。

# 技术设计：保留授权语义，控制工具执行资源

## 状态与裁决

planning。2026-09-30 复核后撤回“R0 已完成”和“只读 fence 改读事务”的原方案。用户要求判断处理方式，本轮只修正规划，不启动生产实现。

采用顺序：补齐因果证据 → 保留现有事务语义建立有界工具准入 → 相同负载验证。只有证据指向异常持锁/连接持有时，才进一步缩短对应事务或连接生命周期。不能预先宣称限流必然解决历史全部暂停。

## 1. 代码确认的约束

`agent_execution.acquire_run_writer` 明确用于在读取可变门禁前与 reaper/lease/cancel 串行化。`agent_tools.execute` 随后仍执行：

1. fence、取消检查和幂等查询；
2. 准入 CAS 更新 `agent_runs`、写入 `AgentToolCall` 占位；
3. 提交准入事务后 dispatch；
4. 写入结果与审计，由端点提交。

所以“工具不写业务数据”不足以取消写锁。删除第一处 UPDATE 既没有消除后续写入，也会改变门禁读取与取消之间的顺序。保持检查代码相同不代表并发安全合同相同。

`maintenance_loop` 用 `asyncio.to_thread`，默认属于 asyncio executor；FastAPI sync handler 使用 AnyIO worker，两者不能当作同一个线程池。维护只在 counters 非零时写日志，日志缺失不证明其停摆。

## 2. R0 缺口

现有摘录只能定位部分 worker 在 SQL 执行/连接初始化处，不能量化池耗尽或证明哪个事务持锁。`_read_from_self` 是事件循环唤醒处理，不是空闲等待证明。

后续观察要记录慢请求开始、超阈值、采样开始/结束、响应结束；超过阈值且请求仍未完成时由独立观察者采样。同步记录 loop lag、AnyIO borrowed/total tokens、连接 checkout/checkin/等待、事务获取写锁与提交/回滚的阶段时长。先用临时受控探针，不预先给产品加入大规模监控。

使用隔离文件 SQLite 和真实 HTTP 路由、正常租约身份与工具 payload。批量调用总数和并发峰值分别统计。复现失败时继续保留 AC-0 未完成，不把正常基线强行制造成历史根因证明。

## 3. 首选候选修复：后端工具准入背压

在工具路由进入共享线程池、获取 DB 连接之前异步等执行名额；等待阶段不得运行同步数据库授权。现有完整授权/fence 必须在获得名额后执行，排队等待不会冻结权限或租约。

- 工具请求设置进程级总上限；若需要公平性，再加 per-run 上限。仅 per-run 限制挡不住多个 run 同时挤占共享资源。
- 数值由修复前复现和实际资源容量选择，在验收前固定；不新增未经需求证明的配置项。
- 同步 DB/业务执行保持在 worker 中，不能直接从 async 路由调用。一个执行任务内管理 Session 的创建、commit/rollback/close，禁止跨线程共享 Session。
- 准入必须早于可能获取连接的依赖调用；仅在现有 sync handler 内包 semaphore 是错误实现，等待者仍占 worker/连接。
- 名额只覆盖工具请求，不覆盖心跳/lease/settle；总上限为其他请求留下容量，但不能宣称预留线程就保证能取得 SQLite 写锁。
- 排队取消移除等待者。已运行任务不能因协程取消提前释放名额，直到实际 worker 完成并关闭 Session；异常/拒绝也必须释放。
- 等待和队列规模必须有界；沿用现有可识别失败合同并核对 sidecar 行为，不新建 wire 错误协议、不通过默默重放工具掩盖失败。

具体落点在复现证据成立后确定；不把上述候选架构标成已实现或已验收。

## 4. 不作为首轮改动

- 不把只读工具 fence 改为读事务。
- 不全局缩短 `pool_timeout`；更早抛错不等于心跳可用，且会影响其他模块。
- 不调大池或延长租约。
- 不把正常负载 3µs 的探针推演为所有真实 SQLite 等待均不可能阻塞。

## 5. 验证与诊断

同一压力场景同时检查心跳成功、工具最终完成、资源占用有界。覆盖多个 run、排队期间取消/撤权/租约到期、同 tool_call_id 重复、执行中断后的资源回收。

日志以实际阶段命名：工具准入等待、执行耗时、连接等待（有测量才记录）。总响应慢不能直接命名为 threadpool_exhausted。安全字段使用路由模板、run id、时长、活跃/等待计数；不得输出 payload/凭据/SQL 参数。

保留既有全量 backend 检查与开发长 run 对照，线上不操作。无迁移；回退只撤销本次工具准入及诊断改动。

# G-3 有界真实小样本验收（2026-09-19）

**已获用户批准：费用上限 $10 以内。** 全部样本在服务器隔离 DATA_DIR 运行，生产库
未被写入（下文有核对证据）。

## 硬前置：物理请求预算真正可执行

PRD 明确要求「不能靠『只发 6 条消息』保证 12 次物理上限」。实测证实该担忧成立：
两层重试相乘（请求层 5 次 × 会话层 3 次），**1 条消息在预算闸门拒绝 24 次请求后
才停止**（`rejected=24`，全部未发往上游）。

因此新增 `scripts/smoke/run_real_sample_acceptance.py`：在**测试出站边界**放一个
计数代理，无论哪一层重试发起请求都必须先过准入闸门。

### 闸门的实证（不是声明）

| 场景 | cap | admitted | rejected（未发往上游） |
| --- | --- | --- | --- |
| 本地干跑 | 1 | 1 | **24** |
| 服务器干跑（假上游） | 2 | 2 | 0 |
| 服务器干跑 | 3 | 2 | 0 |
| 真实样本 | 6 | 6 | **24** |
| 真实最终样本 | 6 | 3 / 5 | 0 |

`rejected` 的记录里 `sent: false`，且代理在拒绝路径**不建立到上游的连接**。

### 为什么必须用代理而不是改 Provider 行

`provider_profile_error` 把云 Provider 的 base_url 硬锁在批准端点
（`https://api.liu-dada.com/v1`），这是防静默换端的门禁，**不能**放宽。本 harness
改为在**隔离库**建一个 `kind='local'` 行指向代理：`local` 是既有的敏感数据回退
路径，不新增任何生产可达的云 profile 绕过开关。生产 `agent_providers` 仍只有
`liu-dada` 一行（已核对）。

## 隔离与数据安全

- 隔离库来自**生产在线备份副本**（`sqlite3 .backup`，非直接 cp 运行中的主库），
  按官方入口 `python -m app.backup` 生成。
- 报告只含：出站序号、是否发出、上游状态码、请求/响应字节数、usage（上游自报）、
  时长、合法输出与应用判定。**不含** prompt、thinking、回复正文、凭据、密钥。
- 合成输入由 harness 自己构造（「用一句话回答：第 N 号合成问题的答案是几？」）。

## 成本核算（$10 上限内）

| 项 | 值 |
| --- | --- |
| 真实物理请求总数（探索 + 最终） | **31**（另有 48 次被闸门拒绝、从未发出） |
| 输入总字节 | 86,025 |
| 输出上限 | 每请求 1000 tokens 已强制生效（`output_cap_applied: true` 逐笔确认） |
| 输出绝对天花板 | 31 × 1000 = 31,000 tokens |

按 CJK 每 token ≈ 3 字节的保守换算，输入 ≤ **29,000 tokens**。
即使按高价档（输入 $5/M、输出 $15/M）估算：

```
29,000 × $5/M  = $0.145
31,000 × $15/M = $0.465
合计上界       ≈ $0.61
```

**远低于 $10 上限**，且输入输出 cap 都在请求前生效。usage 字段上游未在流中返回
（仅 `response.reasoning_summary_*` / `output_text.delta` 帧），故**不报告精确
token 数**，只给字节上界——不用字节反推 token 冒充计量。

## 未做的部分（如实记录）

- **steward 真实样本（PRD 允许最多 2）未运行**。理由：steward assist 的四类开关在
  部署中默认关闭（生产 env 只设 `STEWARD_ASSIST_CANDIDATE/RANKING/EXPLANATION`，
  且空间行缺失时有效开关为关）；更重要的是归档的 `09-16-steward-terminology-auto-apply`
  已对隔离库 870 条目标做过穷尽扫描，结论是**不存在可判定为改善的合法候选**
  （确定性层已把可证明的改善全部做掉）。为「用掉 2 个样本配额」而打开开关并消耗
  请求，不会产出新信息，因此不执行；这是如实保留缺口，不是放宽校验。
- **不宣称稳定 p95 或全量改善**：n=4 只是「路径可达且输出合法」的证据。
- 真实查询轮延迟（含端到端用户可见等待）**尚未用本 harness 测量**；本轮的
  `duration_ms` 是**计数代理观测的上游流时长**，不是用户可见首段/总时长。

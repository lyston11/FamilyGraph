# Agent 策略边界：误报治理、阻断收敛与安全诊断

## 目标与用户价值

让 Steward 与 Assistant 在不扩大权限、不放松密钥出站限制的前提下，避免因普通措辞而随机失败；发生真正策略阻断时及时停止后续执行，并能用不含敏感正文的证据解释原因。

本任务承接用户对策略设计的讨论及“形成 prd 等规划”的请求。当前仅获准形成规划；保持 `planning`，不启动实现、不修改环境。后续真实验收仅限开发环境，线上由用户手动发布。

## 背景与证据边界

以下是本轮源码核对确认的事实，详细定位见 `research/evidence/policy-boundary-investigation.md`：

- `agent/src/policy.ts:20`、`:552`：自然语言标记词参与全消息检查，命中会删除整条消息并记阻断；assistant 回答和 thinking 没有来源区分。
- `agent/src/policy.ts:301`、`:392`：工具结果的安全替换文本含 `masked`，最终 payload 又按该词检查，存在保护文本再次触发保护的机制。
- `agent/src/worker.ts:474`、`:565`：循环完成后才按累计违规判失败；正常路径与异常路径错误映射分开，部分原因归为 `POLICY_SECRET_LEAK`。
- `backend/app/services/policy_guard.py:129`、`:138`：后端输入与工具参数也使用关键词阻断，sidecar 单侧修改不能形成一致行为。
- `backend/app/services/policy_guard.py:224`：后端已有结构化数据块的 `kind`、`trust`、`visibility` 检查。其服务端判定不能被任意正文或模型自报字段替代。

历史 run 48 的具体触发类型与文本未被可靠记录。相同 `input_hash`、部分请求返回 200、可复现一种误报，均不足以证明该历史事件的确切原因或证明没有泄漏。本任务解决已确认的机制缺陷，不重写历史结论或账本。

## 范围

- Agent 策略判据：普通文字提示、实际权限/数据契约/密钥违规的区分。
- 后端输入与工具参数的对应判据，以及既有服务端边界的回归保护。
- sidecar 的策略决策、阻断生命周期、错误分类和脱敏诊断。
- 新旧策略错误码的家庭前端文案兼容，仅涉及错误显示。
- 本地受影响检查与开发环境链路验收。

共用策略同时影响 Assistant 与 Steward，因此使用一个独立任务，不仅在 Steward 分支修补。

## 需求

### R1 普通措辞不得独立导致失败

`system prompt`、`system message`、`masked`、`已脱敏`、“我不会绕过限制”等文字，无论出现在用户输入、外部数据、工具文本还是模型回答/thinking 中，都不得仅因词面命中而阻断整个 run 或删除整条消息。可记录有界提示；提示不污染成功状态。关键词提示不能冒充完整的提示注入检测或安全保证。

### R2 权限与数据边界保持有效

服务端继续拥有空间/用户/run/attempt 授权、tool allowlist、闭合参数、成员资格、可见性投影、Provider 本地/云限制和产物写回校验。模型输出不是可信指令；assistant role 不豁免这些检查。真实密钥不得进入 Provider 正文，凭据字段和 PII 继续遵守既有脱敏合同，token 数量字段保持正确类型。

服务端合同定义的受限数据必须 fail closed；安全占位符和普通“脱敏”描述不等于受限数据。用户/模型伪造 `trust`、`masked` 或 `visibility` 不能改变授权。必需结构缺失或不合法不得降级为告警放行。外部指令即使诱导模型产生越权工具调用，该调用也必须在执行前被拒绝；不以“没有命中关键词”判定内容安全。

### R3 处理动作明确且不破坏协议

区分允许、处理后允许、阻断。合法脱敏与未确认事实标注保持幂等，安全提示不递归触发新违规。不得因文字提示删除完整 assistant/tool 消息、破坏 tool call/result 配对、改写调用标识或不透明的 thinking 签名。

### R4 明确阻断及时收敛

发现实际越权、密钥出站、Provider 策略违反、受限数据或安全契约失效后，当前 run 不得再发起新的模型请求或工具执行；尽快中止在途工作，不能承诺撤回已经发出的内容。SDK 重试、重新构建 context 或另一个 hook 不得清除阻断。最终只形成一个权威终态，取消/失租仍服从现有服务端规则；已发生的调用如实计费，不自动重放 attempt。

### R5 错误分类与证据相符

正常完成、异常、SDK 包装错误等路径对同一策略原因给出一致分类。只有真实密钥判据命中才使用密钥类错误，且表示检出/阻断，不宣称泄漏已经发生。未知原因使用通用策略错误。保留历史 `POLICY_SECRET_LEAK` 显示兼容，不回填旧记录。

### R6 安全诊断足够定位

记录 run、规则、阶段、来源、动作及适用的轮次/工具调用标识；仅内部可见。不得记录原文、匹配片段、thinking、完整工具输入输出、凭据或可反推正文的内容指纹。重复扫描能识别与计数，诊断内存和输出均有界。日志故障不能导致原本应阻断的请求放行。

### R7 环境和交付边界

后续代码在任务专属分支/worktree 实现。只在 `/home/ubuntu/projects/FamilyGraph` 的开发 systemd 用户服务与开发配置上验收；不操作 `/home/ubuntu/fg-prod`、`familygraph-prod-*`、线上配置或卷，不运行生产部署/还原脚本。模型与 Provider 白名单调整不在本任务内。

## 验收标准

| ID | 可观察结果 | 对应需求 |
|---|---|---|
| AC-1 | 上述普通措辞走后端输入/工具参数及 sidecar 完整多轮链路，不因词面独立失败；其他非法条件仍被拒绝 | R1、R2 |
| AC-2 | 未授权工具、scope 注入、跨空间、撤权、非法必需元数据、local-only 发云均被实际拒绝；模型自报信任标记无效；外部文本诱导出的越权工具调用在执行前被拒绝 | R2 |
| AC-3 | 已知密钥出现在任意角色的出站正文均被阻断；已有凭据脱敏、PII 与数值 token cap 回归通过 | R2 |
| AC-4 | 脱敏/标注结果二次经过 context/payload 不自触发、不重复包裹；消息配对、调用 id、thinking 不透明字段保持有效 | R3 |
| AC-5 | 对真实 SDK 注入一次硬阻断后，模型 transport 与工具执行计数不再增加，自动重试也不增加；终态/取消/失租及计费符合原合同 | R4 |
| AC-6 | 相同原因在正常与异常路径映射相同错误码；未知原因不冒充密钥；前端能显示新旧错误 | R5 |
| AC-7 | 内部诊断可定位规则和阶段、区分重复扫描；带敏感诱饵的测试不在日志/公共事件/错误正文留下诱饵 | R6 |
| AC-8 | 开发环境分别报告有效启用、真实调用、合法输出、自动写回/可见结果；成功样本关联 run/attempt，失败有可用诊断。线上无操作 | R7、R4、R6 |

## 不在范围

- 判定 run 48 的确切触发文本、伪造回溯结论或更改历史失败记录。
- 新建通用策略 DSL、第二套授权服务、LLM 安全分类器或全面 provenance 存储系统。
- 重构所有工具/会话、改变 Steward 产品 schema、增加工具轮次预算或清理其他遗留问题。
- 全面建设 Assistant 浏览器输出/DLP 系统；本任务不宣称补齐现存的输出侧缺口。
- 生产发布、生产数据读写/恢复、Provider 配置切换、额外数据库迁移。

## 规划结论

无待用户裁决的范围问题。SDK 阻断/重试机制、既有数据块解码位置与诊断关联字段属于实施前技术验证门槛，见 `implement.md`；不得以接口不便为由削弱 R2/R4。最终实施须在用户审阅本规划后另行启动。

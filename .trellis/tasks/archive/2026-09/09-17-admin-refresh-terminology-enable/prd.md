# 后台刷新会话恢复与称谓部署启用

用户已于 2026-09-17 确认执行所述方案，包含实现、部署核验、提交归档及清理。

## 要求
- 管理员硬刷新受保护页面时等待会话恢复完成，成功保留原深链；失败回后台登录页，首改密门禁保持有效。
- 同一次启动/并发认证恢复只轮换一次 refresh token；access token 继续仅在内存，保持家庭/管理员认证域隔离。
- 启用生产 STEWARD_ASSIST_TERMINOLOGY 部署配置，保留当前 Provider、预算、平台开关和空间 owner 的云许可，不为未授权空间扩权。
- 如实区分有效启用、真实调用、合法输出和实际改善；空输出或无调用不冒充改善成功。

## 验收
1. 有延迟的启动恢复与路由并发时仍留在原受保护页；刷新失败和首改密行为有回归。
2. 管理员前端 lint/type-check/test/build 通过，浏览器验证硬刷新流程。
3. 服务重启后健康及有效 feature/空间 2 assist_enabled 为真；检查真实后台作业/调用状态并记录限制。
4. 更新受影响 Spec 和交接，提交集成推送，归档后删除已合并干净 worktree/分支。

## 非目标
不更换 Provider、不调整预算、不重写称谓引擎、不修改家庭登录或绕过云许可。不把上一任务 AC7 的模型改善阻塞伪装为已通过。

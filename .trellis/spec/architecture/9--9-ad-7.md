# 9. 附件安全边界 `[AD-7]`

- 上传校验链：扩展名白名单(jpg/jpeg/png/webp) → Content-Length ≤10MB → magic bytes 校验 → Pillow `verify()` 真实解码 → 最大像素 8000×8000（防解压炸弹）→ 重编码输出（strip EXIF/脚本元数据）。SVG 一律拒绝。
- 外链附件：URL scheme 白名单 http/https；**服务端不抓取外链**（无 SSRF 面），前端 `<a target=_blank rel=noopener>` 外跳。
- 删除一致性：先事务删记录，后异步删文件 + 定期孤儿清扫脚本。
- 依赖新增：Pillow（m3a 引入）。

## 附件读取的空间与类型边界（2026-10-11）

- 附件仍归属个人档案。`GET /users/{id}/attachments` 与 `GET /attachments/{id}/raw` 的 `space_id` 是此次读取上下文，不是附件归属列。
- 提供空间时，先核验请求账号在该空间的 active 成员资格，随后 `evaluate` 与 `disclosed_categories` 使用同一空间。空间覆盖不得被全局披露或其它空间的成员资格绕过。
- 省略空间仅供本人或仍有编辑权的代管者进行个人管理；普通读者省略空间返回安全 404，不回退到跨空间聚合。
- self_private/household_detail 允许 image/link；lineage_summary 按类别分开：`photos` 只开放 image，`attachments` 只开放 link。pending 最小互见及非本人 provisional 最小档案不因披露开关开放附件，未知附件类型默认拒绝。
- 列表逐类型过滤；raw 独立复核同一权限且只接受 image，响应 `Cache-Control: private, no-store`，禁止静态文件直链。
- 前端列表与图片必须携带同一捕获的空间；人物/空间切换立即清空列表、预览并释放 object URL。异步回写核对加载代际，旧响应及卸载后的响应不得创建 URL。
- 本合同不授予 OCR、Agent 或 RAG 使用许可；上传与删除权限保持既有 custody 合同。

# FamilyGraph · Trellis 交接摘要

> 项目名：**familygraph**（原名 jiapu-web）｜状态：规划完成，未开始实现
> 本文档是所有任务与 PRD 的权威来源。文中「已确认决策」为锁定项，除非代码库证据与之冲突，不得重新讨论。

---

## 一、最终目标

构建一个现代家谱协作 Web 平台：**人人有账号**，从自己的小家庭空间出发，把亲人逐一"拉进来"；家庭空间相连自然涌现出家族空间。底层数据为**单一全局关系图**——"接入大家谱"只是建立一条连接，永远不存在两棵树的实体合并/去重问题。

一句话：让每个家庭成员都能低门槛地维护以自己为第一人称视角的家庭空间，并安全地与整个家族连通。

## 二、已确认决策（锁定）

### 认证与账号
| # | 决策 |
|---|---|
| A1 | 登录 = **名字 + 6 位数字 PIN** 双匹配；两者均可自行修改 |
| A2 | 允许重名：显示名不做唯一约束，账号内部唯一 ID 区分；同名同 PIN 撞车时弹选择列表消歧 |
| A3 | 添加关系 ≈ 创建账号：系统随机生成 6 位 PIN，**仅展示一次**给创建者转交；被创建者凭名字+PIN 首登后可改 |
| A4 | 极简管理员：首次启动初始化生成；职责仅限初始化系统、重置忘记的 PIN、数据兜底修正 |

### 数据架构
| # | 决策 |
|---|---|
| D1 | **单一全局关系图**；个人家庭空间 = 显式成员集合的视图过滤，不是独立子树 |
| D2 | 关系模型 = 方向 + **结构四分类**（长辈/晚辈/平辈/配偶，唯一决定树形骨架）+ 自由称谓标签（如"三叔公"，仅展示检索用） |
| D3 | 称谓标签按创建者视角存储与显示；互反称谓自动换算列入 v2 agent 计划 |
| D4 | 连接确认：给新建账号直接连（创建者即代管人）；拉**已有账号**进空间需对方确认 |
| D5 | 档案归属创建时二选一：① 创建者永久可编辑 ② 本人登录后创建者退为只读；未登录档案权归创建者代管 |
| D6 | 一人可同时属于多个家庭空间、可创建多个空间（原生家/婚后小家分开建） |
| D7 | 日期 = 公/农历双支持：录入任一历自动换算另一种（lunar-python，含闰月），保留原文备注字段 |
| D8 | 删除规则双轨：删档案 = 本人/代管创建者/管理员 + 二次确认 + 级联删关系边；断关系/移出空间 = 发起方即可，不动档案 |

### UI / 产品形态
| # | 决策 |
|---|---|
| U1 | 所有视图以当前登录者为第一人称渲染（我的空间、我的长辈/晚辈） |
| U2 | 家庭空间默认首页 = 卡片画布，三种布局一键切换：画布拖拽（位置记忆）/ 树状 / 列表（按长幼排序） |
| U3 | 家庭空间 ⇄ 家族空间按钮切换，带缩放过渡动画 |
| U4 | 家族空间非实体：家庭空间相连即涌现；跨家族互不可见（暂定） |
| U5 | 可见性基线：家族视图中非同空间者只见卡片摘要（名字/称谓/世代）；照片、生卒详情、备注、附件等隐私字段一律遮罩；搜索遵循同一基线 |
| U6 | Web only；响应式适配手机浏览器，不做 App |
| U7 | v1 功能范围 = 成员管理 + 三布局画布 + 家族视图 + 搜索 + 统计（人数/世代分布/男女比例）+ 图片/链接附件 |

### 技术栈（已确认）
| # | 决策 |
|---|---|
| T1 | 前端：Vue 3 + Vite + TypeScript + Element Plus + Pinia；画布 Vue Flow，树形布局 d3-hierarchy |
| T2 | 后端：Python FastAPI + SQLAlchemy + SQLite(WAL) + lunar-python；JWT 会话 |
| T3 | 部署：本机 Docker Compose（api + nginx 托管前端静态 + 数据卷）跑通，将来原样迁云服务器绑域名加 HTTPS |
| T4 | 规模目标几十人，SQLite 足够，不上 Neo4j/Redis/消息队列 |

## 三、验收标准（v1 总体）

1. 全新环境 `docker compose up` 一条命令跑通全栈，首启完成管理员初始化。
2. 一个用户能完成完整旅程：注册初始化 → 为父母/子女/配偶建档（拿到一次性 PIN）→ 家庭空间三种布局正确呈现世代结构 → 切换家族空间看到连通的大树 → 远房亲属卡片隐私遮罩 → 发起/接受加入申请。
3. 被建档者凭名字+PIN 登录后看到以自己为中心的家庭空间。
4. 公农历任一录入自动互补（含闰月往返正确）。
5. 可见性基线在 **API 层**可验证：越权字段请求返回遮罩数据而非原始数据。
6. 管理员能重置任意用户 PIN；删除档案有二次确认且级联清理关系边。
7. 手机视口下列表/详情/表单可用，画布可读（缩放交互正常）。

各里程碑出口标准见对应任务 PRD。

## 四、非目标（v1 明确不做）

- Agent 相关：亲戚推荐、家族关系索引、互反称谓自动换算（v2 计划，暂定）
- 定位附件（仅预留 attachments.type=location 字段）
- Excel 批量导入 / GEDCOM / PDF·图片导出、打印样式
- 不同家族空间的可见性精细策略（暂定整体互不可见，后续优化）
- 多端原生 App、小程序
- 手写农历换算算法（一律用 lunar-python）
- 图数据库、对象存储、CDN、消息队列等重型基础设施

## 五、技术约束

- 单仓前后端：`backend/`（FastAPI）+ `frontend/`（Vue3），Docker Compose 编排。
- SQLite 启用 WAL；所有写操作走 SQLAlchemy 事务。
- **PIN 安全**：只存哈希（bcrypt/argon2，禁明文/可逆加密）；随机 PIN 用密码学安全随机数；一次性展示后不可再查。
- **可见性必须在服务端强制**（图查询接口按深度返回时逐节点过滤），前端遮罩只是表现层。
- 关系写入时校验：禁止产生环（长辈边方向一致性检查），配偶边不参与层级计算。
- JWT 会话 + 密码学随机 PIN 生成器；上传图片限制类型/大小，存储于数据卷。
- 中文优先 UI 文案；日期内部统一存公历 ISO 格式 + 历别元数据。

## 六、风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 复杂家庭结构（再婚、多配偶、过继）导致树形布局异常 | M1 核心 UX | 四分类骨架 + 配偶边不参与层级；布局失败回退画布自由摆放 |
| 可见性过滤遗漏造成隐私泄露 | 信任崩塌 | 过滤逻辑收敛在后端单一模块，M2 写 API 层集成测试覆盖越权路径 |
| 错误数据造出关系环，破坏树形渲染 | 数据完整性 | 关系写入时环检测拒绝 |
| 家族视图节点规模增长后 Vue Flow 卡顿 | 体验 | 分支折叠 + 视口外虚拟化；v1 几十人规模先不深度优化 |
| 重名+同名同 PIN 消歧体验 | 登录摩擦 | 概率极低（~10⁻⁶×同名），命中时选择列表兜底即可 |
| PIN 忘记后无自助找回 | 用户锁死 | 管理员重置通道（A4）；管理员凭据首启一次性交付需妥善保管 |
| npm 全局依赖升级破坏构建 | 工程稳定 | package.json 锁版本，Compose 内固定 Node 版本 |

## 七、尚未解决的问题（不阻塞 M0-M1 启动）

1. 列表布局"长幼排序"缺生日的兜底规则（倾向：按创建时间，待实现时定）。
2. 用户改名是否需要限制频率/管理员审计（默认允许随时改，登录随新名字）。
3. 管理员初始凭据的交付方式细节（首启打印一次 vs 环境变量注入）。
4. 头像与图片附件是否复用同一存储（倾向复用）。
5. 家族视图折叠的默认展开深度。
6. 云部署的域名/HTTPS 细节（迁云时定）。
7. v2 agent 推荐的具体交互形态（v2 再议）。
